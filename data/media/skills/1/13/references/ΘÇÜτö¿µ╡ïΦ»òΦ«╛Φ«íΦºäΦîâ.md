# 通用测试设计规范

## 动态选择测试方法

根据当前原子需求类型选择，不机械套全量方法：

| 需求类型 | 优先方法 |
| --- | --- |
| 输入字段、枚举、格式 | 等价类、边界值、错误推测 |
| 阈值、区间、计算公式 | 边界值、决策表、数据对账 |
| 状态和审批流 | 状态迁移、非法迁移、回退与幂等 |
| 多条件业务规则 | 决策表、组合覆盖、优先级冲突 |
| 页面列表和查询 | 条件单选/组合、默认值、排序、分页、空结果 |
| 批处理和异步任务 | 部分失败、重试、幂等、并发、超时、结果一致性 |
| 权限 | 角色-资源-操作矩阵、前后端双重鉴权 |
| 接口 | 参数、鉴权、幂等、错误码、契约、数据一致性 |
| 文件导入导出 | 格式、模板、行列、顺序、精度、异常文件、容量 |

安全、兼容和性能只有在需求、知识库或项目策略明确要求时计入测试范围；AI经验补充必须标记 `ai_extension` 并单独展示。

## 可执行性

- 测试点必须包含对象、条件、操作和可判定结果。
- “正确、正常、合理、符合预期”必须展开为明确断言。
- 阈值保留运算符和单位；状态保留起点、操作和终点。
- 组合场景只保留会改变业务结果或风险显著的组合。
- 待确认规则可以生成候选分支，但必须标记待确认，不能选一个分支当作事实。

## 去重

验证目标、前置条件和预期结果均相同的测试点合并；仅测试数据不同且属于同一等价类时使用参数化表达。疑似重复由AI标记，最终由人工确认。
