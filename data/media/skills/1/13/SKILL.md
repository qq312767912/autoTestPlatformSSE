# 星企航通用系统测试设计

## 适用范围

用于需求分析、测试方案编写和测试用例生成。每次任务以用户当前提供的需求文档、附件、已确认图片和指定知识库为输入，动态识别系统、版本、模块、页面、接口、规则和数据依赖。

不要继承其他迭代的功能事实。除固定测试环境地址外，skill 中不得固定某个版本、功能名称、数据库表、字段数、阈值、状态、设备清单或模块路径。

## 固定环境

- 星企航测试环境基础地址：`https://star.test.sseinfo.com/`
- 具体菜单、路由、页面控件和接口路径仍以本次需求、知识库和页面感知结果为准。
- 如用户明确指定其他环境，本次任务使用用户指定环境并在产物中记录，不修改上述默认值。

## 必读规范

- Step1 读取 [`references/质量评估与追溯规范.md`](references/质量评估与追溯规范.md)。
- 需要测试设计方法时读取 [`references/通用测试设计规范.md`](references/通用测试设计规范.md)。
- 当前任务需要的业务规则从用户指定知识库检索，不把知识库全部内容无差别注入上下文。

## 事实来源优先级

1. 本次需求正文、表格和本次已确认图片；
2. 本次产品、开发、测试确认结论；
3. 本次附件、接口文档、数据字典、原型和输出样例；
4. 当前页面感知结果；
5. 用户指定知识库中与当前模块匹配的规则；
6. 历史方案和历史用例；
7. AI测试经验补充。

低优先级来源与高优先级来源冲突时写入 `冲突清单.xlsx`，不得静默选择。知识库内容必须带文档名、章节或知识条目ID；无法定位来源的知识不能作为确定断言。

## 图片与页面感知

- 需求图片在模块拆分后识别，用户可调整所属模块、结构化内容和采用状态。
- 只有人工确认的图片识别结果才能进入原子需求；保留文档名、页码、图片ID和所属模块。
- 图片内容采用“视觉AI结构化结果优先、OCR仅兜底”的单一路径：视觉AI结果完整、语义连贯且无异常时，直接采用视觉AI结果，不再把OCR全文并入需求上下文。
- OCR漏字、乱码、表格错位或与可靠视觉AI结果不一致，属于识别质量问题，不属于业务冲突，不写入 `冲突清单.xlsx`。OCR只在视觉AI结果缺失、关键字段为空、解析失败或明确低置信度时补充证据。
- 只有视觉AI结果本身无法确定，或者其业务内容与需求正文、文档表格、附件、确认结论或可定位知识库规则冲突时，才写入冲突清单。
- 图片占位符在发送AI前临时展开，不修改原始文档内容。
- 当前页面需要感知时，通过平台配置的页面感知/Playwright MCP读取页面标题、URL、控件、表格列、状态、可见文本和交互条件。
- “需求截图”和“当前页面”分别保存来源，比较新增、删除、修改和未实现项；页面现状不能覆盖需求预期。
- MCP不可用或用户未授权访问页面时，记录感知缺口，不得猜测页面内容。

## 工作流

### Step1：需求与知识分析

读取 [`subSkills/RequirementAnalysis.md`](subSkills/RequirementAnalysis.md)，输出：

- `原子需求清单.xlsx`；
- `冲突清单.xlsx`；
- 可选平台内部结构化缓存，不作为人工审核件。

先交用户确认原子需求和冲突。未确认内容保留 `needs_clarification`，不能伪装成确定需求。

### Step2：测试方案

读取 [`subSkills/TestPlan.md`](subSkills/TestPlan.md)，输出 `测试方案.xlsx`，至少包含：

- 测试方案；
- 测试方案明细；
- 需求覆盖关系；
- 待确认项。

AI只做结构自检，不给八项质量指标打分，不写“真实覆盖率100%”。

### Step3：测试用例

读取 [`subSkills/TestCases.md`](subSkills/TestCases.md)，输出 `测试用例.xlsx`。模块层级、前置条件和字段结构从当前项目配置、用户模板或本次需求动态获得。

### Step4：执行与报告（仅在用户要求时）

读取 [`subSkills/TestExecution.md`](subSkills/TestExecution.md) 和 [`subSkills/TestReport.md`](subSkills/TestReport.md)。执行方式根据当前系统选择页面、接口、数据或组合测试；不得假设固定导入导出流程。

## 人工审核产物规则

凡需人工阅读、确认、修改或回填的产物必须使用 `.xlsx`：原子需求清单、冲突清单、测试方案及覆盖关系、生成结构自检、测试用例、人工评审后的AI质量评估结果、执行校验明细。

JSON只允许作为平台内部临时数据或接口载荷，不得作为人工审核交付物。

## 公司模板

- `templates/test_plan_template.xlsx` 和 `templates/test_cases_template.csv` 是公司固定格式，必须保留并优先复用。
- 生成内容时匹配模板字段、顺序、工作表、样式和编码，不因通用化改变公司格式。
- 模板中若存在示例业务内容，只复用格式，不把示例内容当成本次需求事实。
- 用户提供更新版模板时，本次任务使用更新版，但不得删除skill内的默认公司模板。

## 输出目录

默认 `{OUTPUT_ROOT}/{项目或系统}_{需求或版本}_{日期}/`，由平台或用户确定。不得使用固定功能名作为目录。

```text
{OUTPUT_ROOT}/
├── 原子需求清单.xlsx
├── 冲突清单.xlsx
├── 测试方案.xlsx
├── 生成结构自检.xlsx
├── 测试用例.xlsx
├── AI质量评估结果.xlsx        # 人工评审后可选
├── execution/                 # 用户要求执行时
└── 测试报告.html              # 用户要求报告时
```

## 禁止事项

- 不得直接套用固定模块清单。
- 不得为了凑场景机械生成正向、反向和边界。
- 不得把通用安全、兼容、性能内容标成需求明确要求；此类内容标记 `ai_extension`。
- 不得在存在未解决冲突时写出确定性断言。
- 不得用AI自己抽取的需求和自己生成的测试点计算真实覆盖率、准确率或人工接收率。
