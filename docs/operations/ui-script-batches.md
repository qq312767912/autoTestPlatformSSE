# UI脚本批量调度与共同角色

## 批量配置角色

选择最多100条UI用例，点击“批量配置角色”，一次维护一组角色矩阵。保存将替换所选用例的默认矩阵，脚本仍只有一份，每次执行遍历矩阵中所有角色。角色支持保存待完善配置，执行前必须补齐登录态与身份校验。

## 本次执行的角色

“批量执行”弹窗可沿用各用例默认配置，也可勾选“本批次统一使用下方角色”。后一种选择只记录在批次快照，不修改任何用例默认角色。每个角色仍使用独立浏览器上下文，并生成独立记录和整组汇总。

## 调度

- 通过 `/api/ui-automation/script-batches/` 创建持久批次；旧WebSocket批量入口也统一入此队列，不再按用例数预占槽位。
- 首版专用 `ui_execution` solo worker串行派发，每次使用一个执行单元。100条用例不需要100个浏览器。独立执行器暂忙时等待其一个空闲槽位，最多等待15分钟，再明确反馈。
- 未指定执行器时使用录制器浏览器，支持后台串行批量执行；独立执行器支持普通脚本批量，角色展开目前仍需录制器浏览器。
- 业务断言失败继续下一条；执行器长期不可用或整条执行没有回执时暂停后续派发，避免反复占用资源；关闭弹窗不停止后台任务。进度可重开查看；停止请求会停止当前执行及后续派发，保留证据。
- 角色配置保存和新批次创建检查同项目、权限及活动批次冲突；队列中的角色快照固定，不受后续默认配置变更影响。
- 批次列表展示每条用例进度、整组记录及各角色记录。此入口只跑脚本，不依赖大模型或自愈Skill。

## 部署

同步部署迁移0027、Web代码、前端及新增 `celery_ui_execution` worker。任务路由为`ui_automation.run_ui_script_batch` → `ui_execution`。只更新路由不启动消费者会造成任务一直排队。按现有内网实际文件制作最小补丁，勿用本地settings整文件覆盖内网旧版。已有批量转换、自愈任务不需取消。

日志：`/app/data/logs/ui_execution_worker_err.log`。主进程采用`solo`；不要将100条任务直接转换成100进程并发。首版没有自动扩展并发或跨批次公平轮转。
