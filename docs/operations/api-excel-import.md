# 旧接口自动化平台 Excel 完整导入

入口：接口自动化 → 场景用例 → Excel 导入。兼容 AutomationTestCase / AutomationCaseApi 多工作表导出的 .xlsx 和 .xls，先解析预览，再确认。需要新增接口定义、接口用例、场景用例、接口环境及环境变量权限，以及项目成员身份。

## 迁移内容

- 每个旧请求建立原生 ApiInterface 定义和一条 ApiInterfaceCase；接口用例包含一个 main 步骤，携带当前请求、断言、所需变量及环境配置，可独立执行。
- 原来的用例组合保留为 ApiTestCase 场景及有序步骤，origin_interface 指向同一接口定义。场景的 excel_migration.assets 记录源请求 ID 对应的接口/接口用例 ID。
- 用例、请求步骤及顺序、请求头、查询参数/表单/原始请求体、HTTP 状态与 JSON 断言。
- GlobalHost 创建项目接口环境，保留名称、地址、说明和启用状态。同名同地址复用；同名不同地址使用独立导入名称，不改动已有环境。
- 从历史请求参数、请求头补齐旧数据源变量。按记录时间选择最新可用输入，保留每个值的工作表、行号和时间来源。
- 断言预期仅恢复历史校验配置中明确的 jsonAssertValue，绝不从 jsonPathResult 或实际响应生成预期。历史 token 等值可能过期，用户可在用例/环境中更新。
- 恢复值同时进入用例变量和导入环境变量；已有环境变量不覆盖。变量确实无法恢复时，在发起请求前阻止执行，明确列出待补值。用户显式定义 null/空值可用于负向测试。
- 全部工作表原始行保存到项目级 ApiExcelImportArchive（正文使用 SECRET_KEY 派生密钥加密）。包括历史记录、关联映射、历史响应及源脚本数据；不会伪造成本平台新执行报告，不执行源脚本。编辑用例时点击“查看导入源数据”，可以按工作表分页核对。
- 脚本/数据库检查等无法可靠迁移的执行逻辑仍明确报错，不会静默丢弃检查或自动执行导入代码。

## 补全已有导入

同一项目、同一文件 SHA256、同一源用例 ID 和名称可选择“补全此前导入的用例”。补建缺少的接口定义/接口用例、关联现有场景步骤，并添加缺失变量、环境与源数据档案关联，保留已有步骤、请求、断言和用户变量。非本文件导入的同名资产仍阻止导入。整个操作为事务，不部分写入。

历史数据作为源数据保留，并恢复最近一组已记录输入；不会把全部历史记录自动作为新执行次数。原外部数据库未导出的额外数据和逻辑无法凭空恢复。

## 部署

执行 python manage.py migrate api_testcases（迁移0006）后更新 Web 和前端。已有 openpyxl/xlrd 依赖不变。SECRET_KEY 更换后旧档案无法解密，需保留原密钥或重新导入。

限制：文件20MB、解压100MB、单表50000行及100列。XLSX 公式要求转为值。

接口资产补建以当前场景快照为准，不用旧 Excel 覆盖已编辑请求。同文件补全复用资产映射及源请求标识；同名的非本次导入接口用例使用明确的 Excel 后缀区分，已有原生资产的编辑不被覆盖。新增关联不启用自动同步覆盖，沿用平台原有同步配置。接口用例编辑保存保留迁移元数据。
