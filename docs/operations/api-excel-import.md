# 旧平台 Excel 导入接口与接口用例

入口：接口自动化 → 接口用例 → Excel 导入。兼容 AutomationTestCase / AutomationCaseApi 多工作表导出的 .xlsx、.xls。先预览，再确认；导入后不自动执行。

## 领域映射

- AutomationCaseApi 建立接口定义。旧分组ID映射为接口模块；源文件没有名称时明确命名为“旧平台分组 ID”，缺少分组ID时按原用例名归类。已有接口手工模块不覆盖；重命名后继续按已记录模块ID复用。
- AutomationTestCase 按原始用例边界建立接口用例，保留其中全部请求、数据、断言和顺序，不按请求强拆用例。
- 当前样例建立4个接口定义、2条接口用例，每条用例包含2个请求；正常导入不创建场景用例。
- 沿用平台现有接口用例结构：最后一个请求为归属接口/main，其余有序请求使用前置步骤存储；所有请求及其断言均由运行器依次执行。导入编辑页以“请求步骤”展示并说明归属接口。
- 接口用例可以通过任意请求引用的接口筛选，不仅按末步接口筛选。

## 环境与数据

GlobalHost 创建接口环境，保留名称、地址、说明及启用状态。同名同地址复用，同名不同地址独立命名，不覆盖已有变量。恢复历史请求输入及明确的 jsonAssertValue 预期配置，保留来源和时间，不把实际响应变成预期。历史 token 可能过期。

恢复值进入用例变量和环境变量；确实缺失的迁移变量会在请求前报错。用例显式 base_url 沿用现有执行优先规则，可在用例配置中修改。

全部工作表原始行加密保存到 ApiExcelImportArchive，包括59条历史数据、映射和历史响应；接口用例编辑页可查看导入源数据。归档记录不会自动转成执行次数或新测试报告，不执行源脚本。复杂脚本/数据库校验等无法可靠迁移的逻辑明确报错。

## 原导入记录的纠正

勾选“补全或迁移此前导入的记录”：
- 同一项目、文件SHA256、源用例ID识别已有资产。
- 旧版误建的场景迁入接口用例，原拆分接口用例合并回原始用例边界。
- 接口定义复用；保留用户编辑请求与变量。场景和拆分用例分别修改且冲突时，事务回滚并要求核对，不擅自选取。
- 旧记录和报告保留，通过ID可回溯；旧场景/拆分记录从默认列表移出，执行时提示改用新接口用例。
- 已完成迁移的接口用例为权威版本，重复导入不覆盖其编辑或重复创建。
- 历史任务若引用旧记录，需要改选新的接口用例。场景侧旧导入URL仅为兼容旧客户端保留，实际导入目标同样是接口用例。

需要新增接口、接口用例、接口模块、环境及环境变量权限；补全需要修改接口用例权限，补齐已有接口的模块还需要修改接口权限，迁移旧场景还需修改场景权限。所有操作限定当前项目并在事务内完成。

## 部署

已有迁移0006需已应用，本次无新增数据库迁移。更新前端/Web，以及执行服务所在进程；已有运行任务可待结束后更新。现有 openpyxl/xlrd 依赖不变。SECRET_KEY 用于归档加密，须保持稳定。

限制：文件20MB，解压100MB，单表50000行、100列；XLSX公式须转为值。
