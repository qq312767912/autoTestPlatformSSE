# UI用例角色参数化

## 使用

1. UI自动化 → 测试用例 → 编辑，在“执行角色”添加业务要求的所有角色。
2. 在“配置角色”中填写角色名称、对应账号、密码和万能验证码（默认 A1ad）；游客勾选“游客”，不需要账号。
3. 展开“共同登录方式”，设置登录页、账号/密码/验证码输入框、登录按钮和仅在登录后可见的成功标记 CSS。这组角色共用配置，新增角色沿用；填写账号后使用自动登录。没有账号的旧配置仍兼容登录态及身份校验。
4. 选择“录制器浏览器”单条执行，按配置顺序串行运行全部角色。每个角色启动独立浏览器会话，用例页面步骤原有登录态不覆盖角色身份。
5. 画面显示当前角色和序号，结束后展示各角色结果、记录ID。执行记录列表增加执行角色；另有一条整组汇总记录，供转换绑定、自愈等原有流程读取。

## 通过规则与边界

- 所有要求角色都运行且通过，整条用例才通过；前一个失败不阻断下一个，最后一个成功不能掩盖前面的失败。
- 自动登录配置可保存草稿；缺少登录控件或成功标记时禁止执行，不会静默按游客运行。密码使用项目绑定的 Fernet 密文保存，回显只含密文引用，密码输入框留空保留原值。SECRET_KEY 更换后须重新录入密码。
- 登录步骤在 trace 和画面转发之前完成，失败不继续执行业务步骤；错误不包含密码，登录步骤不采集失败截图。旧登录态缺失、禁用、跨项目或执行环境不匹配时仍明确报错。
- 本版复用相同脚本及业务断言；角色间业务流程或断言明显不同时应拆用例。不自动推断未知角色的权限规则。
- 身份检查使用原有文本断言语义（包含匹配）；应选取唯一账号/角色标识，而不是“用户”等通用文本。
- 明确声明“遍历角色：…”的描述可自动建立待配置角色；转换绑定还校验源用例中明确声明的全部角色，缺少覆盖时不能把游客单次执行当作完整成功。
- 本版全角色串行执行，不提供单角色调试选择或只重跑失败角色。修复公共脚本后重新执行整组，保留完整覆盖证据。
- 批量配置与本次统一角色执行见 `ui-script-batches.md`；录制器浏览器支持后台角色批量串行执行。独立执行器仍不展开角色矩阵，会明确拒绝以免静默只运行一次。

## 部署
