# v2.9.2 Skill runner 分批适配（2026-11-16）

本批合入独立执行面、命令护栏、用户凭据隔离、结构化审计、临时工作区和产物回传。不会迁移或覆盖 Skill 原始目录；本地正式入口的切换结果见下方部署记录。

## 执行边界

Backend 每次核对所选精确版本的可运行状态与包指纹，再发送文件快照。runner 不挂载业务数据、Skill 库、Docker socket 或后端工作区。传输逐文件核对 SHA256，拒绝越界路径、重复路径和符号链接；源版本不由 runner 修改。

独立 Alpine Python/Node 镜像预装基础依赖。容器 UID 10001、只读根、tmpfs、cap_drop ALL、no-new-privileges、1GiB内存、2CPU、256进程。执行网只接 Backend 和 runner，不接 Postgres/Redis/Qdrant；容器有出站网络，不等同于断网或目的地址白名单。Docker 跨网直连隔离已经以模拟存储服务验证。

每个 runner 同时只执行一个作业，作业结束清理临时目录，并回收进程组及脱离原组的后台子进程。服务控制进程禁用 dumpable，避免作业读取父进程凭据。子进程不继承平台环境，只注入当前用户的有效 API Key 和平台 API 地址；不使用运维级 Key。日志只记录上下文、版本、命令指纹、耗时与返回码，不记录请求凭据。

命令通过 argv 执行，不经过 shell；入口限定到版本包内脚本。运行期依赖安装、内联代码、模块启动、重定向、管道和环境前缀等不受支持。脚本本身仍是代码，真正的隔离边界是容器、文件挂载和网络，而不是启动器白名单。

| 限额 | 值 |
| --- | --- |
| 版本文件快照 | 24MiB / 2000文件 |
| 单次执行 | 最长120秒 |
| 客户端队列 | 同进程串行，等待最多150秒 |
| 批量调用 | 最多50条，工作线程最多16 |
| stdout/stderr | 各256KiB，超出标记截断 |
| 产物回传 | 合计8MiB / 20文件 |
| 请求／响应 | 40MiB / 16MiB |

产物校验路径、大小和指纹后，回到 Backend 原有的独立产物目录。runner 输出的任意绝对路径不会触发 Backend 读取、复制其他文件。

## 浏览器兼容方式

runner 是无状态作业，不维持跨命令浏览器进程。沙箱模式新增 `platform_browser` 平台基础工具，按会话和登录态隔离；UI生成继续使用已验收的 `ui_generation_browser`。二者执行平台自己的浏览器适配代码，不执行上传 Skill 的任意脚本，不属于本次 Skill runner 容器。

交互支持 open/snapshot/click/fill/get/eval 等现有基础操作。只允许无内嵌凭据的HTTP(S)页面，拒绝本地文件导航和启动参数；登录态更新时重新初始化上下文。旧 Skill 中的持久浏览器 CLI 命令会收到明确的适配提示，不静默回退。复杂浏览器 CLI 的所有高级子命令尚不保证功能对等。

## 开启与回滚

为保持旧部署兼容，未配置 `SKILL_EXEC_MODE` 时沿用 `inprocess`。这是兼容模式，不是本批沙箱。明确启用 `runner` 后，服务失联、包校验或策略失败均拒绝执行，不自动回退；拼错模式同样报错。

标准部署在环境文件中配置独立随机 `SKILL_RUNNER_TOKEN`，叠加执行：

```sh
docker compose -f docker-compose.yml -f docker-compose.skill-runner.yml build skill-runner
docker compose -f docker-compose.yml -f docker-compose.skill-runner.yml up -d
```

镜像使用阿里云 Alpine/PyPI 源，依赖在构建期安装。离线环境在联网机器构建、导出镜像后 `docker load`，目标机不运行 pip/npm 安装。当前已准备并校验 ARM64 镜像包，约59MiB；麒麟64KB页目标机仍须单独验证。内网域名通过容器 DNS 或 runner 的 `extra_hosts` 配置，不修改宿主机 `/etc/hosts`。

单独回滚执行面时恢复上一份本地活动 Compose，或明确设置 `SKILL_EXEC_MODE=inprocess` 后重建 Backend。无需恢复数据库或回写旧 Skill 包。Docker 原数据盘的指向修复与功能回滚无关，不应切回新空盘。
