# 内部代码审查金标保存

代码审查结果经逐项人工标记后，可保存为内部金标测评资产。数据使用既有数据库中的金标数据集、版本、样本及初标记录，不放在容器临时目录或浏览器缓存中。本次无需新增数据库表或迁移。

## 使用入口

1. 代码审查 → 打开已完成、降级完成或部分完成的任务 → 保存内部金标。
2. 填写数据集名称，逐项选择确认问题、误报或待复核；误报必须填写判断依据，遗漏项不允许保存。
3. 代码审查 → 内部金标集 → 查看快照，可查看人工结论、原始代码变更、快照指纹并导出完整快照。

目前入口针对含风险项的审查结果；不把没有风险项的报告自动认定为无缺陷金标。

## 保存契约

- 服务端从当前任务读取代码变更、审查报告、测试报告、上下文、提交编号和已有模型/提示词/精确技能版本来源；客户端只能提交人工标记，不能伪造源报告。
- 快照保存的是差异与报告上下文，不是完整代码仓库镜像。缺少的版本来源保持为空，不补造记录。
- 标记按原始风险项序号对应，保存前比对快照指纹；原任务在标记期间变化时拒绝保存。
- 同数据集中的相同输入和标记重复保存复用原样本；标记变化创建新版本，不覆盖旧样本。
- 样本不依赖原任务外键。原任务重跑、修改、删除或容器重建都不会覆盖、删除已保存快照。
- 保存范围为当前项目，隐私为内部，默认禁止用于优化。单人标记形成初标记录和待独立复核样本，不直接变成已确认、已冻结金标。正式复核、仲裁、冻结沿用既有治理流程。
- 单份源快照上限16MB，超出明确拒绝，不截断代码证据。
- 正常版本升级应沿用当前数据库与数据卷。此功能不替代数据库备份；删除数据库卷、删除项目等显式数据删除操作不属于“保留”的保证范围。

## 权限

保存需要修改代码审查任务、添加金标用例权限，以及项目成员身份。新建内部数据集还需要项目负责人身份（项目拥有者或管理员）；已有数据集可由获授权成员追加样本。查看样本需要查看代码审查任务、查看金标用例权限和项目成员身份。没有跨项目权限绕过。

## 验证
