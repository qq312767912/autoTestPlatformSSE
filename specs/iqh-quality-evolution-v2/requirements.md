# IQH质量飞轮、测评与受控自进化V2 - 需求规格

## 目标

把现有统一产出、反馈、评测、知识候选和能力版本底座升级为：

```text
真实产出 -> Badcase -> 金标 -> L0-L3测评 -> 节点归因
-> 优化候选 -> 隐藏/影子验证 -> 测试负责人审批 -> 发布/回滚
```

## 角色

- 测试执行人员：反馈、初标、补充证据、确认或驳回归因。
- 测试负责人：复核、仲裁、冻结金标、配置量表、审批晋级与回滚。
- 不新增知识管理员。

## 业务范围

- 单次测评：用例审查、代码审查、知识问答。
- 链路自进化：风险识别 -> 测试方案 -> 用例生成 -> 测试执行 -> 问题跟踪。

## 核心需求

### R1 金标资产

- 真实缺陷、误报、漏报、编辑、失败、回滚可生成金标候选。
- 支持双人标注、冲突仲裁、版本冻结和不可变快照。
- 支持 gold、regression、fresh、challenge、hidden 五类分区。
- 隐藏集答案不能暴露给优化器。

### R2 L0-L3分层测评

- L0：Schema、引用、链路、工具、隐私和可解析性。
- L1：量表、必须项、禁止项、规则裁判和LLM陪审团。
- L2：采纳、驳回、编辑、确认缺陷、误报、漏报和测试结果。
- L3：风险、方案、用例、执行、问题的端到端结果。
- 各层必须使用不同数据源，不能复制同一分数。

### R3 节点轨迹与归因

- 记录理解、规划、检索、Prompt、模型、工具、校验、交接、人工编辑和下游执行Span。
- 支持理解、规划、知识、检索、Prompt、工具、生成和下游执行失败分类。
- 规则优先，LLM只提供带置信度的辅助归因，最终支持人工确认。

### R4 受控优化

- 支持Prompt、知识、检索策略、Skill/工具配置四类候选。
- 候选关联Badcase、归因、差异、影响范围、风险和回滚方案。
- 候选依次通过金标、回归、挑战、隐藏和影子验证。
- 未经测试负责人审批不得生产生效。

### R5 真实业务接入

- 八类真实入口必须产生完整统一产出，仅注册适配器不算完成。
- 必须包含证据、问题项、版本、链路、反馈目标和真实上下游关系。
- 飞轮写入失败不得阻断原业务。

### R6 UI

- 业务结果页复用统一质量侧栏。
- 测试负责人页面拆分金标、评测、归因、优化和版本发布。
- 保持平台现有浅色、蓝色主色、卡片和表格规范。

## 非功能要求

- 项目隔离、权限审计、敏感信息脱敏。
- 数据集、评测、裁判、Prompt、模型、知识和工具版本可追溯、可重放。
- 协议向后兼容，使用增量迁移。
- 任一能力版本可回滚。

## 非目标

- 自动微调基础模型。
- 无人审批发布生产版本。
- 完整专家市场或外部A2A平台。
- 为飞轮重写八个业务模块。

## 完成定义

- 真实代码审查Badcase完成金标、测评、归因、候选和晋级闭环。
- 一个真实五阶段流程完成端到端追溯和测评。
- 八个入口通过真实集成测试。
- 所有新增和历史回归测试通过。
