# LLM 探索绑定登录态——需求

## 1. 问题与目标

WHartTest 已能在 UI 自动化录制和执行中保存、绑定并注入 Playwright
`storageState`（cookies + localStorage），但 LLM 会话直接调用 Playwright MCP
探索页面时不会读取该登录态。对含 SSO/滑块验证码的内网系统，LLM
因此无法进入登录后页面。

本功能的目标是：用户在 LLM 会话中显式指定已保存的环境登录态后，系统
由服务端将其注入本次 Playwright MCP 探索上下文，使 LLM 在不接触明文凭据
的情况下探索登录后页面。

## 2. 用户故事

1. 作为测试人员，我希望说“使用「星企航测试账号登录态」测试某页面”，
   LLM 可直接进入登录后页面。
2. 作为安全管理者，我希望 Cookie/token 只在 Backend 和浏览器上下文之间传递，
   不进入 LLM 提示词、工具参数、模型输出或普通日志。
3. 作为测试人员，我希望在登录态过期、不存在或名称不唯一时获得明确提示，
   而不是让 LLM 猜测凭据或反复尝试登录。
4. 作为测试人员，我希望同一次 LLM 探索中的后续页面操作继续使用同一
   浏览器上下文，不在每个工具调用前重复注入。

## 3. 功能需求与验收标准

### R1. 显式选择登录态

- 当用户在 LLM 探索请求中选择或明确指定一个登录态时，系统应将该
  `auth_state_id` 绑定到本次浏览器探索会话。
- 当用户未显式选择登录态时，系统应使用无痕上下文，不得默认注入某个
  环境的登录态。
- 当用户仅提供登录态名称时，系统应在当前用户有权访问的登录态中解析；
  当名称不唯一时，系统应要求用户选择，不得自行猜测。

### R2. 服务端安全注入

- 当已绑定有效登录态且浏览器上下文尚未初始化时，系统应由 Backend
  读取 `UiAuthState.state_json` 并在服务端注入 Playwright 上下文。
- 在任何情况下，系统不得将 cookies、localStorage token 或完整 `state_json`
  加入 LLM 消息、提示词、模型可见工具参数、普通应用日志或审批文本。
- 当并发 LLM 探索使用不同登录态时，系统应隔离浏览器上下文，不得串用
  Cookie/token。

### R3. 登录态有效性与失败处理

- 当登录态不存在、已停用、不属于用户可访问范围或 Cookie 已明确过期时，
  系统应在导航前终止并返回可操作的错误信息。
- 当登录态注入后仍被重定向到已知登录页/SSO 页时，系统应停止登录后探索，
  并提示重新录制登录态，不得自动尝试绕过滑块。
- 当登录态有效时，系统应允许 LLM 在同一探索会话内继续导航、点击、读取页面，
  不重新创建上下文。

### R4. 界面与对话交互

- 当用户发起 LLM 页面探索时，系统应提供可选的环境和登录态选择能力，
  并仅展示名称、所属环境、凭据摘要和过期状态。
- 当用户在对话文本中指定登录态名称时，系统应显示实际绑定结果，
  例如“已使用：星企航测试账号登录态”，但不得显示凭据内容。

### R5. 审计与生命周期

- 当登录态被用于 LLM 探索时，系统应记录使用者、登录态 ID、名称、会话 ID、
  目标 origin、开始/结束时间和结果，但不记录凭据内容。
- 当 LLM 探索会话结束、用户切换登录态或会话超时时，系统应关闭对应
  浏览器上下文并清理临时凭据载体。

## 4. 约束

- 复用现有 `UiAuthState` 数据模型和 Playwright `storageState` 格式，不新建一套
  凭据存储。
- 登录态必须显式绑定；“环境存在登录态”不等于自动授权 LLM 使用。
- 支持 SSO 跨域 Cookie 和目标 origin 的 localStorage。
- 不将“自动解滑块”或“绕过生产风控”纳入本功能。
- 不影响未绑定登录态的现有 LLM 探索流程。

## 5. 非目标

- 不自动从用户名/密码生成新登录态。
- 不向 LLM 提供任意 Cookie 读取/导出工具。
- 不保证跨设备指纹、出口 IP 强绑或服务端强制单会话系统的凭据可复用性。
- 不以本功能取代认证平台为测试环境提供的白名单/测试开关。

## 6. 临时过渡方案（内网尚未部署本功能）

1. **首选：SSO 测试白名单**。对专用测试账号 + Actuator/Playwright MCP 出口 IP
   关闭滑块，仅限测试环境。
2. **现有能力：UI 自动化绑定登录态**。用“环境配置 → 登录态 → 录制登录态”
   人工完成一次滑块，再将该登录态显式绑定到 UI 用例步骤执行。
3. **LLM 过渡用法**。先由上述 UI 用例采集登录后页面的截图、DOM/文本和执行结果，
   再交给 LLM 分析；在本功能部署前，不将明文 Cookie 复制到 LLM 对话。
