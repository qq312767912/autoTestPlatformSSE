# 代码审查内置公开测评集：需求

状态：待确认实施。本文只定义需求，不表示公开数据或运行器已经接入。

## 目标与边界

在「质量飞轮 → 数据飞轮 → Agent 独立测评 → 代码审查」直接选择内置的 SWE-CARE、SWR-Bench、AACR-Bench，完成准备、运行、核验和报告。公开集不要求用户下载、上传 JSON 或逐个登记公开仓库。内部集保留现有项目级 JSON 导入。公开数据及仓库快照须有固定版本、校验和隔离；生产环境可通过离线包预置。

三个基准不能共享未经说明的分母或把结果合成一个排名。SWE-CARE 与 SWR-Bench 的公开数据以 Python 为主；AACR-Bench 只纳入其真实存在且可解析的 Python、Java、C++ 样本。缺失语言显示「未覆盖」，不得补造样本。SWR-Bench 的 500 条干净 PR 是误报基线，不能把全部 1000 条都称为负例。

## 用户故事与验收条件

**R1 内置目录。** 当用户进入代码审查独立测评时，系统应展示三个固定公开集的来源、适用语言、样本规模、数据版本、许可说明、准备状态和上次校验时间。公开集不得展示文件上传框；内部集才展示导入入口。未准备、准备失败、可运行状态须明显区分。

**R2 数据准备。** 当测试负责人发起公开集准备时，系统应从受控官方来源取得固定版本数据，验证 SHA256/样本数量/样本 ID 唯一性，转换为统一协议并生成不可变数据版本。网络不可达时应允许导入运维提供的同版本离线包，但不把该操作暴露为业务用户的「公开集导入」。转换失败的样本须记录原因，不得静默跳过。

**R3 仓库快照。** 当公开样本进入运行前预检时，系统应按样本的仓库、base/head Commit 准备隔离的只读代码快照；不得要求在项目仓库列表中登记 GitHub 仓库，也不得修改用户仓库。须限制允许的来源域名、仓库路径、下载大小、并发和磁盘配额；失败样本应可定位并可重试。离线运行须使用预置快照。

**R4 运行。** 当用户选择公开集、固定数据版本、样本范围（先小样本，后全量）并点击运行时，系统应先显示预计样本数和预检结果。只有所有选中样本满足必需数据与快照条件才可提交，或用户明确选择「仅运行可用样本」并在报告中记录排除清单。运行复用当前标准代码审查，不缩小 Diff 文件覆盖。每次运行锁定样本 ID、数据版本、审查模式、模型配置与代码版本。

**R5 评价。** 当审查完成时，系统应区分候选自动匹配和正式人工核验；正式召回、准确率、误报率只基于已核验且成功完成的样本。失败、取消、部分完成、未核验样本单列，不得混入质量指标分母。报告按基准、语言、正/负例、仓库与样本展开，并展示 Token、耗时、缺陷证据、来源与失败原因。各基准原生评分口径需单列，不能用平台口径冒充官方分数。

**R6 复现与权限。** 当用户查看或导出报告时，系统应能追溯到官方来源、固定版本/校验和、转换器版本、仓库快照 Commit、样本清单、模型和运行配置。项目成员可查看本项目运行；准备/更新全局公开数据与清理缓存仅限授权维护角色。不同项目可复用只读公共数据，不共享运行报告或凭据。

**R7 兼容与回退。** 现有内部 JSON 测评集、既有运行记录和报告保持可用。旧的 `source=public` 手工导入停止在界面提供；后端应拒绝新的伪公开导入或按迁移规则标记为「历史自定义集」，不得自动认定为官方集。新能力不可用时原代码审查功能保持可用。

## 非目标

- 不把公开数据加入训练/自进化数据池；从测评反馈到知识资产的回流须另行审批，防止测评集泄漏。
- 不在本次实现 C++ 人造样本、自动 LLM 裁判取代人工核验、跨基准单一总分或排行榜。
- 不重新设计整个质量飞轮或修改 Skill Hub。
