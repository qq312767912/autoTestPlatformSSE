# 项目级质量飞轮与阶段门禁 - 需求规格

## 范围

- 显示当前项目真实 owner、admin、member，并映射为测试负责人和测试执行人员。
- 将用例审查、代码审查、知识问答作为单次能力飞轮独立呈现。
- 将测试方案、测试用例、测试执行、报告生成作为四阶段 Skill 质量链路呈现。
- 四个阶段都必须关联 Skill 能力版本，支持失败回流、归因、影子评测和受控发布。
- 金标资产必须按业务能力和数据分区组织。
- 连续链路只有在上一阶段质量门禁通过或由负责人留痕放行后，才能进入下一阶段。

## 验收标准

1. 当用户进入质量飞轮时，系统应展示当前项目真实负责人和执行人员。
2. 当用户查看金标资产时，系统应按业务类型分组并支持类型筛选。
3. 当存在相同 workflow_id 的多阶段产出时，系统应按固定阶段顺序展示可视化流水线。
4. 当上一阶段门禁未通过时，系统应将下一阶段标记为阻塞。
5. 当测试负责人强制放行时，系统应要求填写原因并记录操作者和时间。
6. 当阶段存在评测结果时，系统应从 L0-L3 结果计算门禁状态，而不是只使用前端展示状态。
7. 单次能力飞轮与连续链路不得混排为同一列表。
8. 当四阶段 Skill 产出失败时，系统应将失败样本归因到对应 Skill 版本并支持生成优化候选。

## 非目标

- 本阶段不重写方案、用例、执行和报告模块本身。
- 不允许无人审批绕过失败门禁。
