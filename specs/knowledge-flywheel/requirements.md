# 知识数据飞轮与自进化机制需求

## 1. 背景与目标

当前平台已具备文档解析、分块、PostgreSQL 元数据、Qdrant 稠密/稀疏混合检索、Reranker 精排和代码仓库图谱。本改造要将一次性文档和任务产物升级为可检索、可追溯、可评测、可增量和可回滚的知识资产，并形成“使用—反馈—评测—晋级—再使用”的数据飞轮。

“自进化”特指受治理的知识、检索策略和 Agent 能力版本迭代，不等于在生产环境中无审核地改写提示词、Skill 或模型权重。

## 2. 核心领域对象

- **原始证据（Evidence）**：文档原文、代码、测试结果、对话、人工评审等不可由推理结果覆盖的来源记录。
- **知识候选（Knowledge Candidate）**：从证据中提炼出、未经晋级的结构化知识，可能重复、冲突或过期。
- **知识资产（Knowledge Asset）**：通过质量门禁后可在生产检索中使用的版本化知识单元。
- **知识版本（Knowledge Version）**：资产某次发布的不可变快照，保留来源、审批、有效期和回滚链路。
- **检索轨迹（Retrieval Trace）**：一次 LLM/Agent 调用从问题到候选、精排、图扩展、最终引用及输出的完整记录。
- **反馈事件（Feedback Event）**：用户采纳/驳回/修改、测试成败、缺陷确认、误报/漏报等可归因到输出和知识版本的事件。
- **评测集（Evaluation Suite）**：由固定金标、历史回放和新鲜样本组成的版本化检查集。
- **晋级门禁（Promotion Gate）**：决定候选知识或新策略能否进入生产的自动指标与人工审批规则。

## 3. 范围

### 本期范围

1. 文档、代码图谱、需求、测试用例、测试结果、代码审查结果和人工反馈的统一来源模型。
2. 文档知识的版本化、证据链、分级、冲突、过期和回滚机制。
3. 向量、关键词、图谱和结构化过滤的融合检索。
4. 对 LLM/Agent 输出的引用、反馈、评测、影子对比、晋级和回滚。
5. 在知识图谱工作台中查看文档图谱、冲突、证据与资产状态。

### 非目标

- 不在第一阶段自动微调基础模型。
- 不允许仅凭 LLM 自评将候选内容直接发布为核心知识。
- 图谱不替代原文存储、PostgreSQL 事实账本或 Qdrant 候选召回。
- 不将单次用户点赞直接视为可复用知识。

## 4. 功能需求与验收标准

### R1 — 统一知识来源与证据链

- 当文档、代码快照或任务产物入库时，系统应生成不可变的来源快照标识、内容哈希、项目权限边界和来源定位。
- 当任何知识资产、图节点或 LLM 输出被查看时，系统应能追溯到其来源快照和具体位置。

### R2 — 知识提炼与分级

- 当来源快照处理完成时，系统应产生文本分块、实体、关系、规则候选和摘要候选，并保存提取器及提示词版本。
- 当知识候选生成时，系统应根据约束力、证据强度和适用范围将其归入 L1 强制、L2 应当参考或 L3 可选参考。
- 当 L1 知识没有权威证据或未经人工审批时，系统不得将其发布为可强制执行的资产。

### R3 — 去重、冲突和生命周期

- 当新候选与已有知识语义近似时，系统应展示合并、新版本、共存或驳回建议，而不是静默覆盖。
- 当两条知识在同一适用范围内给出不兼容结论时，系统应创建冲突记录并在解决前降低检索信任或禁止自动执行。
- 当资产超过有效期、来源更新或代码快照失效时，系统应将其标记为待复核、过期或已废弃，不得继续无提示地作为高信任知识使用。

### R4 — 多路检索与图谱增强

- 当 LLM/Agent 提交查询时，系统应并行生成稠密向量、稀疏关键词、结构化过滤和图谱邻域候选，并通过可配置融合策略精排。
- 当查询涉及代码影响、跨文档概念、需求—用例—缺陷链路或来源追溯时，系统应使用图谱扩展候选。
- 当普通文本查询已有足够高信任的直接命中时，系统可跳过图扩展，以控制延迟和成本。
- 当组装 LLM 上下文时，系统应保留全部任务必要输入；图谱和检索结果只增强上下文，不得用于减少代码审查等流程的必要覆盖。

### R5 — 检索轨迹和可解释输出

- 当检索被 LLM/Agent 消费时，系统应记录查询、改写、召回通道、各阶段候选、分数、最终引用、模型/策略版本、Token 和耗时。
- 当输出显示给用户时，系统应能将关键结论对应到具体证据，并显示证据的版本、权限和新鲜度。

### R6 — 反馈和二次经验蒸馏

- 当用户采纳、驳回、编辑或标记输出时，系统应将反馈关联到任务、输出、检索轨迹和具体知识版本。
- 当任务有可验证结果时，系统应优先用测试通过/失败、缺陷关闭、代码合并或回退等客观信号，而不是只用点赞作为质量信号。
- 当同类反馈达到最小样本量且去重后，系统应生成经验候选，不得直接改写生产知识。

### R7 — 评测、影子运行和晋级

- 当新知识版本、检索策略、提示词、Skill 或 Agent 候选产生时，系统应在固定金标、历史回放和新鲜样本上与当前生产版本对比。
- 当候选版本未达到指标门槛、安全约束或 L1/L2 人工审批要求时，系统不得将其晋级。
- 当候选版本通过离线评测时，系统应先支持影子运行或小流量对比，再由有权用户发布。
- 当发布后指标恶化或出现严重反例时，系统应能在不重建原始数据的前提下回滚到上一个生产版本。

### R8 — 防腐化与定期重建

- 当定期健康检查运行时，系统应检测断链证据、过期资产、孤立图节点、向量/数据库/图谱不一致、异常反馈和质量漂移。
- 当索引、图谱或处理器版本发生不兼容变更时，系统应从不可变来源快照重建派生索引，并在切换前校验数量、哈希和评测指标。

### R9 — 权限、安全与审计

- 当检索、图扩展、评测或反馈聚合运行时，系统应在所有候选生成前执行项目、文档和知识级权限过滤。
- 当用户无权访问某条证据时，系统不得通过图关系、摘要、日志或评测样本泄露其内容。
- 当发生知识发布、冲突解决、策略晋级、回滚或删除时，系统应记录操作人、理由、前后版本和时间。

### R10 — 指标与数据飞轮看板

- 当管理者查看飞轮运行状态时，系统应展示召回覆盖率、引用率、采纳率、证据支持率、冲突率、过期率、评测通过率、晋级/回滚次数、Token、耗时和单次有效结果成本。
- 当统计自进化效果时，系统应按生产版本、项目、任务类型和时间窗口对比，不得用不同样本结构的绝对数直接宣称改进。

## 5. 第一阶段验收边界

1. 可从一个现有知识库生成文档图谱，并在统一图谱工作台展示文档—分块—实体—关系—证据。
2. 一次检索可生成完整 Retrieval Trace，并能对结果做采纳、驳回、修改和原因标注。
3. 反馈只生成知识候选；经离线评测和人工审批后才能发布。
4. 新旧检索策略可在同一回放集上对比准确率、召回率、引用正确率、Token 和耗时。
5. 生产知识和检索策略均可一键回滚，原始证据不会被覆盖。

## 6. 默认产品决策

1. L1 强制知识需业务专家与项目管理员双重审批。
2. 首期同时接入测试结果、缺陷状态和代码合并/回退，并区分信号强度。
3. 知识资产默认有效期按 L1/L2/L3 设置，允许知识库在不降低 L1 保护的前提下覆盖。
4. 首期只做纯影子对比，候选版本不直接响应真实用户；小流量对比留待后续独立决策。
