# 技术与交互设计

## 界面设计规格

1. **目的**：在不改变现有 WHartTest 信息架构的前提下，为审查任务补充可追溯文档上下文、任务生命周期操作和安全的仓库清理能力，并提升批量配置及录制窗口的可用性。
2. **视觉方向**：工业化工具界面；沿用项目现有 Arco Design 组件和品牌规范，避免引入新的视觉体系。
3. **颜色**：沿用现有主色与状态色；主操作 `#165DFF`、成功 `#00B42A`、警告 `#FF7D00`、危险 `#F53F3F`、中性背景 `#F7F8FA`。
4. **字体**：沿用项目既有字体栈，避免此次增量功能造成全局排版变化。
5. **布局**：审查表单采用“基础信息 + 文档上下文”分区；知识库与文档使用级联分组多选；域名批量导入采用左侧粘贴、右侧解析结果的宽抽屉；录制窗口使用可调整大小的视口约束弹窗。

> 本次是现有后台系统增量功能，项目设计系统优先于通用 UI 风格规则。

## 数据与接口

- 代码审查任务新增/复用 `requirement_document_ids`，并增加 `knowledge_base_ids`、`knowledge_document_ids` JSON 字段；序列化器执行项目归属、权限和文档状态校验。
- 用例审查任务增加同构字段，创建、详情、重跑接口保留文档选择。
- 审查服务按已选需求文档正文和知识库文档检索结果构造受长度限制的上下文，并记录来源 ID 便于追溯。
- 域名模块新增批量解析/导入接口；服务端再次解析与校验，前端预览不能代替后端校验。
- 用例审查提供明确的 `rerun`、`cancel` 动作，后台任务在耗时阶段之间检查持久化取消状态。
- 代码仓库提供 `purge-local-copy` 动作，仅清理平台为 OCR/审查生成的受管容器副本；不改变代码审查任务删除行为。

## 安全与一致性

- 所有文档查询限定当前用户可访问项目。
- 删除本地副本使用 `Path.resolve()` 后验证必须位于配置的受管仓库根目录之下，拒绝符号链接越界与根目录本身。
- 清理、取消、重跑接口保持幂等或返回明确冲突状态。
- 批量 hosts 导入复用现有 IPv4/hostname 校验器，导入后仍为草稿。

## 测试策略

- Django：文档权限与状态校验、批量 hosts 解析、取消竞态、重跑、任务删除、本地仓库安全删除。
- Vue：类型检查与构建；覆盖多选联动、解析预览、滚动区、按钮状态和可调整窗口。
- 回归：无文档审查、单条域名维护、现有代码审查取消/重跑、登录态保存及截屏操作。
