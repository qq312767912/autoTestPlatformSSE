# 审查与域名配置体验优化需求

## 范围

本次优化覆盖代码审查、用例审查、测试域名配置及 UI 自动化录制窗口，不改变现有审查算法、报告格式和域名同步机制。

## 用户故事与验收标准

### R1 代码审查引用文档

- 当用户新建代码审查时，系统应允许多选当前项目下的需求文档。
- 当用户启用知识库资料时，系统应先选择一个或多个知识库，再按知识库分组展示其中可用文档，并允许多选具体文档。
- 当任务创建后，系统应固化所选文档 ID，并在执行时只使用用户有权访问且状态可用的文档。
- 当文档被删除、越权或未完成解析时，系统应拒绝创建任务并明确指出不可用文档。
- 未选择文档时，现有代码审查流程应保持兼容。

### R2 用例审查引用文档

- 当用户发起用例审查时，系统应提供与代码审查一致的需求文档、知识库和知识库文档多选能力。
- 当执行用例审查时，系统应把已选文档作为审查上下文，并在任务详情中保留选择快照。
- 未选择文档时，现有用例审查流程应保持兼容。

### R3 用例审查列表滚动

- 当用例审查任务数量超出可视区域时，任务列表应在自身区域出现纵向滚动条，详情区域和页面主操作应保持可用。
- 用户切换任务时，列表不应造成整个页面异常跳动。

### R4 域名批量导入

- 当用户粘贴标准 hosts 文本时，系统应逐行解析 `IPv4 hostname`，支持空行及行尾 `# 注释`。
- 当一行包含一个 IP 和多个域名时，系统应为每个域名生成一条预览记录。
- 系统应在提交前展示有效、重复、冲突和错误行，并允许用户只导入全部有效记录。
- 当域名已存在且 IP 不同，用户应明确选择覆盖；默认不得静默覆盖。
- 批量导入只写入草稿，仍需用户点击发布后才进入现有同步流程。

### R5 用例审查重跑与取消

- 当用例审查处于成功、失败或已取消状态时，有权限的用户应能重跑，并生成一次新的执行记录或重置为可追踪的新一轮执行。
- 当任务正在排队或执行时，用户点击取消后，系统应撤销 Celery 任务、写入取消状态，并让工作进程在后续阶段检查到取消后停止。
- 已取消任务不得继续调用模型、生成报告或覆盖最终结果。
- 重跑与取消的权限、确认提示、状态展示应与代码审查保持一致。

### R6 截屏及登录态窗口缩放

- 截屏窗口和登录态窗口默认尺寸应较当前更大，并适配当前浏览器视口。
- 用户应能拖拽改变窗口宽高；窗口不得超出可操作视口，核心按钮始终可见。
- 放大、缩小窗口时，远程画面应按比例适配，不应裁掉关键交互区域。

### R7 删除容器内代码仓库

- 对本地克隆仓库，有权限的用户应能单独执行“清理容器副本”。
- 操作前应显示仓库名称和容器内规范化路径，并要求二次确认。
- 系统只能删除受平台管理根目录下、数据库登记且路径校验通过的仓库，禁止删除根目录、父目录、软链接逃逸路径或任意用户输入路径。
- 正在被审查任务使用的仓库不得清理。
- 清理容器副本不应删除 GitLab 远端仓库、平台仓库配置或历史审查记录；后续重跑时可重新拉取。

## 非目标

- 不允许通过页面直接填写任意宿主机文件路径。
- 不删除 GitLab、Gitea 等远端真实仓库。
- 不修改现有 hosts 发布后的宿主机及容器同步架构。
