# 技术设计

复用 EvolutionExecutionService、SkillCreatorAdapter 和既有候选版本服务。新增独立 paired_evaluation 模块，使用三个无历史上下文的 LLM 调用（同配置并不代表不同模型），分别比较源数据、业务背景与两份产出；返回偏好、收益强度、证据和退化标记。对模型响应进行严格校验。多数平票不构成提升，任何退化反证保守阻断。

EvolutionExperiment 增加 policy、evaluation_report、parent（一对一）与 round_number。实验链最多三轮，每轮继承上一轮人工胜出版本，输入快照从首轮冻结。报告持久化实际调用次数、估算 Token、时间及停止原因。每次模型调用前检查预算；单次在途调用耗时不承诺硬终止。评测与发布前校验实际包指纹、运行指纹及评测绑定指纹，禁止旧结果复用。

实际重跑保留报告扩展工作表等完整产出。评委必须读取源数据，不能仅比较问题数量。既有 fixed_hits 改为明确未验证的观察值。

下一轮独立派生，不覆盖父实验结果。无收益停止、调用不足停止、弱收益停止、达到轮数停止；人工发布仍走 SkillVersionService。

验证：Django 隔离测试库覆盖偏好投票、失败关闭、预算、输入漂移、版本篡改、下一轮继承及发布闸口；Vue 类型检查与构建。

## 实现细节与部署

- 三个评委采用同一模型配置的独立实例与不同审查侧重；不宣称不同模型的交叉验证。完全相同的实际产出直接判无提升。
- 首轮 A 是确定性最小护栏，B 使用 skill-creator；后续轮次 A/B 在胜出基线上结合上轮观察生成最小/结构变体。只推进版本号的无实质候选被拒绝。
- 候选版本标签包含轮次与实验标识，避免既有 next_version 对实验后缀产生重号；活跃版本保持不变。
- SDK 隐式重试关闭；调用与估算 Token 预算包含候选生成，时间预算按活跃执行时间累计并在调用间检查。大输入不足预算时显式失败，不裁剪评测范围或用干跑顶替。
- 实验历史按项目查询最近 20 项，详情不返回源文档快照；仍按项目权限读取运行产出和评委证据。
- 上线需应用 `knowledge_evolution.0048_evolution_paired_evaluation`，并发布匹配的前后端。本次仅在独立测试库执行迁移，没有更新运行中业务库。
- 本轮验证使用模型测试替身，不消耗真实模型额度；不把测试通过当成真实业务指标已提升。

参考：<https://github.com/alchaincyf/darwin-skill/blob/master/SKILL.md> 的成对比较、独立评委、受控实验与早停方法。没有安装、执行或原样复制该 Skill 的工作流。
