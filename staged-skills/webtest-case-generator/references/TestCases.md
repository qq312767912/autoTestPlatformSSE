# TestCases：测试用例生成（Step 3）

## 功能定位

基于 Step 2 生成的测试方案（`test_plan.xlsx` 中的“测试方案表”），为每个方案项（正向/反向/边界场景）生成详细的测试用例，确保用例可执行、可追溯，并覆盖所有场景类型。

## 前置依赖

- 必须已完成 Step 2，并生成有效的 `test_plan.xlsx` 文件（包含“测试方案表” Sheet）
- 方案表中的字段至少包含：方案编号、模块名称、功能描述、测试场景类型、测试要点、优先级、备注
- 若方案表为空或不符合规范，应提示用户先完成测试方案生成

## 输出格式（Excel）

**文件：** `test_cases.xlsx` 

**Sheet名：** 按功能模块分组，例如“首页模块”、“个人中心模块”等（与方案的一级模块对应）

### 字段定义（顺序固定）

| 字段名       | 类型   | 说明                                                         |
| ------------ | ------ | ------------------------------------------------------------ |
| 用例编号     | 字符串 | 唯一标识，格式：`TC-{模块缩写}-{三位序号}`，如 `TC-HOME-001` |
| 用例名称     | 字符串 | 简明扼要描述用例目的，例如“首页-登录按钮-正向-点击跳转登录页” |
| 优先级       | 枚举   | P0 / P1 / P2 / P3                                            |
| 用例类型     | 枚举   | 功能测试 / 界面测试 / 交互测试 / 边界测试 / 异常测试         |
| 前置条件     | 字符串 | 执行本用例前必须满足的状态（如“已退出登录状态”）             |
| 步骤描述     | 字符串 | 分步描述操作，每步换行或使用数字列表                         |
| 预期结果     | 字符串 | 每个步骤对应的预期结果，与步骤一一对应                       |
| 测试结果     | 枚举   | 生成时置空，待Step 4执行时填充执行结果，包括通过/失败/阻塞   |
| 关联所属需求 | 字符串 | 引用 Step 2 中的方案编号，格式如 `1.1`、`2.3.1`              |

> **关键约束：** 每条用例必须关联至少一个方案编号，且该编号必须存在于 `test_plan.xlsx` 的“测试方案表”中。

## 优先级定义（同方案）

| 级别 | 含义               | 示例                         |
| ---- | ------------------ | ---------------------------- |
| P0   | 核心功能，阻断发布 | 页面加载、搜索查询、列表展示 |
| P1   | 重要功能           | 筛选排序、Tab切换、翻页      |
| P2   | 辅助功能           | 收藏、点赞、评论             |
| P3   | 边界/异常          | 空列表、404、超长输入        |

## 用例类型定义

| 类型     | 说明                     | 适用场景                       |
| -------- | ------------------------ | ------------------------------ |
| 功能测试 | 验证功能正确性           | 正向流程、业务规则             |
| 界面测试 | 验证UI样式、布局、响应式 | 页面元素展示、适配             |
| 交互测试 | 验证用户操作流程         | 点击、输入、拖拽等交互         |
| 边界测试 | 验证边界值输入           | 最大长度、最小值、空值         |
| 异常测试 | 验证错误处理             | 网络异常、服务器错误、非法输入 |

## 生成规则（基于方案）

1. **正向场景** → 至少生成 1 条功能测试用例
2. **反向场景** → 至少生成 1 条异常测试用例
3. **边界场景** → 至少生成 1 条边界测试用例
4. **方案编号映射**：每条用例的“对应方案编号”必须填写对应的方案编号
5. **顺序要求**：用例排列顺序应与方案的大纲顺序保持一致（按方案编号升序）
6. **避免重复**：相同操作 + 不同数据/状态应拆分为不同用例，不可合并

## 用例排序与分组策略（同一 Sheet 内）

- **排序依据**：按“方案编号”升序排列，同一方案编号下按场景类型（正向 → 反向 → 边界）排列
- **模块区分**：通过“模块名称”字段标识所属模块，无需拆分 Sheet
- **可读性**：可在相邻模块之间插入空行（可选），但非强制

## 生成步骤

1. **读取方案表**：加载 `test_plan.xlsx` 中的“测试方案表” Sheet
2. **遍历方案行**：按方案编号升序遍历每一行
3. **根据场景类型生成用例**：
   - 若测试场景类型包含“正向”：生成 1 条功能测试用例
   - 若包含“反向”：生成 1 条异常测试用例
   - 若包含“边界”：生成 1 条边界测试用例
   - 若为组合（如“正向+反向”），分别生成独立用例
4. **填充字段**：
   - 用例编号：按模块生成自增序号
   - 用例名称：组合“模块名称+功能描述+场景类型+核心验证点”
   - 优先级：继承方案中的优先级
   - 用例类型：根据场景类型自动映射（正向→功能测试，反向→异常测试，边界→边界测试）
   - 前置条件：从方案备注中提取，或根据常识补充（如“需要登录态”）
   - 步骤描述：根据功能描述和测试要点转化为可操作步骤
   - 预期结果：根据功能描述和测试要点生成明确的预期
   - 测试结果：保留为空（不写入任何值）
   - 关联所属需求：填入当前方案编号
5. **按顺序写入同一 Sheet**：将生成的用例逐行追加到 `测试用例表` 中
6. **保存 Excel**：生成 `test_cases.xlsx` 文件

## 注意事项

- **不可凭空生成用例**：每条用例必须引用方案编号，确保可追溯性
- **方案变更影响**：若方案表修改，用例应同步更新或重新生成
- **数据依赖**：若方案备注中有“依赖登录态”，用例前置条件中应明确“已登录”
- **避免过度细化**：不建议为单个方案生成超过 3 条用例（除非明显需要）
- **跨模块用例**：若一条用例验证多个方案，可用逗号分隔方案编号，但需确保步骤能同时覆盖
- **用例编号唯一性**：全局自增，不与历史用例冲突（若重新生成，可考虑清空原文件或使用新的版本号）
- **测试结果字段**：生成后保持空白，Step 4 执行时需根据实际执行结果更新该列（写入“通过”/“失败”/“阻塞”）

## 与 Step 2、Step 4 的联动

- **与 Step 2**：生成完成后，可反馈给用户：共生成 X 条用例，覆盖 Y 个方案项
- **与 Step 4**：Step 4 执行自动化脚本时，应同步更新 `test_cases.xlsx` 中对应用例的“测试结果”列，并将详细失败信息写入日志或报告
