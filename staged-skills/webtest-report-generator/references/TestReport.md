# TestReport：测试报告生成（Step 5）

## 功能定位

基于 Step 4 执行完成后的结果（包括回填了“测试结果”列的 `test_cases.xlsx`、截图、日志等），生成可视化的 HTML 测试报告，提供清晰的测试概览、模块分组、用例详情及问题追溯能力。

## 前置依赖

- 已完成 Step 4，且 `test_cases.xlsx` 中“测试结果”列已更新（通过/失败/阻塞）
- 截图目录 `screenshots/` 存在且截图文件命名与用例编号对应
- 日志目录 `logs/` 包含执行日志（可选，用于报告附加信息）

## 输出产物

默认由主 skill 的 `交付物清单-输出目录` 决定，存放于该根目录下：

```
{OUTPUT_ROOT}/
├── test_report.html # 主报告（单文件，可离线查看）
├── test_results.json # 原始数据（用于二次分析或接口调用）
└── screenshots/ # 截图（已在 Step 4 产出，报告会引用）
```

## 报告数据来源

| 数据项                | 来源                                                |
| --------------------- | --------------------------------------------------- |
| 测试用例列表及结果    | `test_cases.xlsx` -> “测试用例表” Sheet             |
| 截图                  | `screenshots/` 目录下与用例编号匹配的 `.png` 文件   |
| 执行配置              | `test_config.json`                                  |
| 开始/结束时间、总耗时 | Step 4 执行记录（或从 `logs/execution.log` 中提取） |

## 报告生成步骤

1. **解析测试数据**：读取 `test_cases.xlsx`，提取每条用例的字段：用例编号、用例名称、模块名称、优先级、用例类型、前置条件、步骤描述、预期结果、测试结果、对应方案编号。
2. **收集截图映射**：扫描 `screenshots/` 目录，建立 `{用例编号}_*.png` → 用例编号的映射。每个用例可关联多张截图，报告中仅展示第一张作为缩略图，点击可查看全部。
3. **计算统计指标**：
   - 总用例数、通过数、失败数、阻塞数
   - 通过率 = 通过数 ÷ (通过数 + 失败数) × 100%（阻塞不计入分母）
   - 按模块分组统计通过率
   - 按优先级统计失败分布
4. **生成 HTML 报告**：输出 `test_report.html`。
5. **生成原始数据 JSON**：序列化统计数据及用例列表，保存为 `test_results.json`。

## 报告 UI 规范

### 整体布局

- 页面宽度 1200px，居中，白色背景，圆角阴影
- 顶部：报告标题、测试环境、执行时间、通过率进度条
- 中部：模块折叠面板（默认全部展开）
- 底部：总结表格（按优先级统计）

### 颜色与状态标识

| 状态 | Badge 背景色 | 文字颜色 | 色值示例                  |
| ---- | ------------ | -------- | ------------------------- |
| 通过 | 浅绿         | 深绿     | bg:#e8f8ef, color:#27ae60 |
| 失败 | 浅红         | 深红     | bg:#fdecea, color:#e74c3c |
| 阻塞 | 浅黄         | 深黄     | bg:#fff8e8, color:#d4900a |

- 所有文字使用中文字体（默认系统字体栈）
- 表格隔行浅灰色底纹（提高可读性）

### 表格列定义（固定百分比）

| 列名     | 宽度 | 说明                                         |
| -------- | ---- | -------------------------------------------- |
| 用例编号 | 5%   | 如 TC-001                                    |
| 模块名称 | 7%   | 从用例中读取                                 |
| 用例名称 | 16%  | 较长的名称需省略 + hover 显示完整            |
| 优先级   | 6%   | P0/P1/P2/P3                                  |
| 预期结果 | 24%  | 多行文本，默认显示第一行，hover 浮层展示全文 |
| 测试结果 | 10%  | 状态 badge                                   |
| 截图     | 9%   | 缩略图（40x40），点击放大                    |
| 验证备注 | 23%  | 失败时显示错误摘要，或手动验证提示           |

> 长文本列（用例名称、预期结果、验证备注）在单元格内设置 `max-width`，超出部分显示省略号 `...`，鼠标悬浮时显示完整内容的浮层（title 属性或自定义 tooltip），双击可复制单元格内容。

### 模块折叠功能

- 按“模块名称”分组，每组一个可折叠行（使用 `<details>` / `<summary>` 或 JS 实现）
- 分组标题显示：模块名称、通过率、失败数/总数
- 默认展开，点击标题可折叠/展开，带有平滑动画
- 折叠图标：▽（展开） / ▷（折叠）

### 通过率计算与展示

- 顶部全局通过率圆环或进度条（使用 CSS 或 SVG）
- 每个模块旁显示该模块的通过率百分比
- 公式：`模块通过率 = 模块通过数 ÷ (模块通过数 + 模块失败数 + 模块阻塞数) × 100%`

## 报告附加内容

- **执行配置摘要**：展示环境、浏览器、执行模式、并发数、重试次数等（从 `test_config.json` 读取）
- **失败摘要**：列出所有失败用例的编号、名称及失败原因（从验证备注中提取）
- **截图查看**：缩略图点击后使用 lightbox 放大查看原图，支持左右切换同一用例的多张截图

## 生成脚本规范

- HTML 骨架 + 响应式 CSS
- 数据占位符（如 `{{ test_summary }}`、`{{ test_cases_rows }}`），生成时用实际数据替换
- JavaScript 实现折叠、tooltip、双击复制、lightbox 等交互

## 与 Step 4 的联动

- Step 4 执行完成后自动触发 Step 5
- 若 `test_cases.xlsx` 中的“测试结果”列为空或全部未执行，报告生成前应提示用户先执行 Step 4
