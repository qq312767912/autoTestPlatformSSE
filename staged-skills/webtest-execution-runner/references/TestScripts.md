# TestScripts：自动化脚本生成与执行（Step 4）

## 功能定位

基于 Step 3 生成的测试用例（`test_cases.xlsx`），生成可执行的自动化脚本（使用 Selenium / Playwright 等框架），执行测试并记录结果，最终更新用例的“测试结果”列，并输出日志、截图等产物。

## 前置依赖

- 必须已完成 Step 3，生成有效的 `test_cases.xlsx`（包含“测试用例表” Sheet，且字段完整）
- 测试环境已准备：Python 3.8+、浏览器驱动（Chrome / Firefox）、必要依赖包
- 目标网站可访问，如需认证（登录态）已提供凭据或会话文件
- 输出目录已确定（由主 skill 的 `OUTPUT_ROOT` 决定）

## 脚本生成规则

### 脚本模板使用

- 浏览器驱动初始化（支持 headless / 有头模式）
- 超时配置（`page_load_timeout`、`implicitly_wait`）

- 截图与日志记录装饰器

- 失败重试机制

- 每个用例生成一个独立脚本文件，命名规则：`TC-{用例编号}_{用例名称缩写}.py`

- 脚本结构：

  ```python
  # -*- coding: utf-8 -*-
  from base import WebTestBase
  import unittest
  
  class TestHomeLogin(WebTestBase):
      def test_login_positive(self):
          """TC-001: 首页-登录按钮-正向-点击跳转登录页"""
          self.driver.get(self.base_url)
          self.click("//button[contains(text(),'登录')]")
          self.assert_in_url("/login")
          self.take_screenshot("TC-001_result.png")
  
  if __name__ == '__main__':
      unittest.main()
  ```

### 特征库复用

- 若存在 `../websiteFeature/{domain}.md`，脚本生成时优先使用其中的元素定位策略（如 `#login-btn`、`.search-input`）和自定义等待逻辑。
- 特征库中的“常见弹窗处理”应自动插入脚本。

### 脚本生成步骤

1. 读取 `test_cases.xlsx` 中的“测试用例表” Sheet
2. 遍历每一行（用例），提取字段：用例编号、用例名称、步骤描述、预期结果、前置条件、对应方案编号
3. 根据“步骤描述”中的自然语言（如“点击登录按钮”），映射到具体的定位方式（可结合特征库）
4. 生成断言：根据“预期结果”内容，转换为 `assertEqual`、`assertIn`、`assertTrue` 等方法
5. 写入脚本文件到 `{OUTPUT_ROOT}/script/TC-{编号}.py`

## 执行配置（用户可调整）

在执行前，用户可通过配置文件（`test_config.json`）或命令行参数调整以下项：

| 配置项             | 可选值 / 格式                       | 默认值   | 说明                       |
| :----------------- | :---------------------------------- | :------- | :------------------------- |
| 执行模式           | `serial` / `parallel`               | `serial` | 串行或并行执行用例         |
| 并发数             | 整数（1-10）                        | 1        | 并行模式下的线程数         |
| 失败重试次数       | 整数                                | 0        | 每条用例失败后自动重试次数 |
| 重试间隔           | 秒                                  | 2        | 重试前等待时间             |
| 超时时间（用例级） | 秒                                  | 300      | 单个用例最大执行时间       |
| 失败快速终止       | `true` / `false`                    | `false`  | 遇到失败是否停止全部       |
| 环境选择           | `dev` / `test` / `staging` / `prod` | `test`   | 影响 base URL              |
| 截图策略           | `always` / `on_failure` / `never`   | `always` | 何时截图                   |
| 浏览器             | `chrome` / `firefox`                | `chrome` | 使用的浏览器               |
| headless           | `true` / `false`                    | `true`   | 是否无头模式               |
| 登录态注入         | 会话文件路径或凭据                  | 无       | 自动登录或加载 cookies     |

## 执行引擎（OpenClaw 环境特别注意）

由于 OpenClaw 的 `exec` 工具有默认 15 秒超时限制，且超时后会强制杀进程树（包括浏览器），脚本执行必须遵循：

**推荐调用方式：**

```python
exec(
    command='python "..\\script\\TC-001.py"',
    background=True,   # 关键：后台执行，避免超时杀进程
    timeout=300        # 足够长，5分钟
)
```

**脚本内部防护（多层超时）：**

- 设置页面加载超时：`driver.set_page_load_timeout(20)`
- 隐式等待：`driver.implicitly_wait(3)`
- 显式等待（WebDriverWait）用于不稳定元素

**常见错误处理：**

- `StaleElementReferenceException`：使用重试包装函数（见模板）
- 网络抖动：`driver.get` 增加重试机制
- 认证过期：执行中检测到登录页跳转，尝试重新登录（需提前配置）

## 结果收集与回填

### 执行结果标准

| 结果     | 定义                                                         | 处理                                         |
| :------- | :----------------------------------------------------------- | :------------------------------------------- |
| **通过** | 所有断言成功，无异常                                         | 更新 `测试结果` = `通过`                     |
| **失败** | 断言失败或未捕获异常                                         | 更新 `测试结果` = `失败`，记录失败步骤及截图 |
| **阻塞** | 前置条件不满足（如环境不可用、依赖服务宕机）或其他需要人工介入确认的情况 | 更新 `测试结果` = `阻塞`，记录原因           |

> **注意**：对于无法自动化验证的步骤（如外部链接跳转后的内容、特定监管文案），脚本应标记为“手动验证”，并在报告中提示，但用例结果可先标记为 **“通过”** （仅验证跳转 URL 或提示文本存在），附加说明“需人工二次确认”。

### 回填 `test_cases.xlsx`

- **【重要】**执行完成后，读取原始 `test_cases.xlsx`，根据用例编号找到对应行，将“测试结果”列更新为实际结果（通过/失败/阻塞）。
- 同时可新增“实际结果详情”列（可选），记录失败原因或截图路径。**注意不要覆盖其他列，基于当前表结构在最后空白列新增。**
- 保存文件。


## 与 Step 3、Step 5 的联动

- **Step 3**：读取其生成的 `test_cases.xlsx`，获取用例列表和步骤。
- **Step 5**：执行完成后，将回填后的 `test_cases.xlsx` 及截图、日志保存，用作下一步报告生成的输入。

## 注意事项

- **环境隔离**：禁止在生产环境执行破坏性操作（如删除数据），可通过配置环境标签自动跳过危险操作。
- **登录态管理**：优先使用 cookies 文件注入，避免重复登录；若使用用户名密码登录，凭据需加密存储。
- **并行执行风险**：并行时需确保用例间无数据冲突（如共用账号导致状态变化），可建议用户使用独立测试账号池。
- **报告预览**：执行过程中可实时输出进度条或简要结果到控制台。
