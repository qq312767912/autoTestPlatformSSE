## 3. 采编 → 基础服务 → 下游 数据链路

```
人工导入 / 上游自动化抽取 / XBRL
        ↓
   采编系统（人工审核通过 / 一次比对）
        ↓  Kafka topic：INFONET_VOTE.DATA
   基础服务（消费、去重、唯一性约束）
        ├→ vote_basic_info（股东大会基本信息表，正常数据）
        └→ vote_basic_info_error（股东大会基本信息异常表，异常数据）
        ↓
   下游：统计系统 / 网站后台（业务管理、预投票）/ H5 子系统 / 业务系统 / 沪港通子系统 / 先行赔付系统
```

【用例实证】关键判定口径：

- Kafka 消息体中**必须包含** `timestamp`（时间戳）字段；基础服务入库的 `timestamp` 值需与 Kafka 消息**一致**。
- 会议变更（公告类型 `新增` / `变更` / `延期` / `取消`）审核通过后：`vote_basic_info` 中**历史会议数据置为无效**，新增会议数据 `timestamp` 与 Kafka 最新一条消息一致。
- 二次比对**不一致**时走"操作强制通过"分支，结果同样要验证。
- 异常数据入 `vote_basic_info_error`：如会议 `meetingId` 在表中不存在、议案缺少 `meetingId`、同一消息重复消费的第二条。

## 4. 采编系统时间戳字段与唯一性约束

### 4.1 背景（需求原文）

> 「因 kafka 组件存在 rebalance 机制，基础服务虽然有去重判断，但是 rebalance 机制下去重判断无法生效导致同一条消息有可能重复消费，导致网站展示会议数据重复。」

### 4.2 规则【需求原文 + 用例实证】

| 项 | 规则 |
| --- | --- |
| 新增字段 | 采编系统会议信息新增「时间戳」`timestamp` |
| 唯一性约束 | 基础服务对 **`会议ID + 时间戳`** 新增唯一性约束 |
| 约束性质 | **组合唯一**，不是单字段唯一 |
| Kafka topic | `INFONET_VOTE.DATA` |

### 4.3 唯一性约束的判定边界【用例实证】

| 场景 | 预期 |
| --- | --- |
| insert 与已有记录「时间戳 + 会议ID 均相同」 | 插入**失败**，表中仍只有 1 条 |
| insert「时间戳相同、其他字段不同」 | 插入**成功**，表中 2 条 |
| insert「时间戳不同、其他字段相同」 | 插入**成功**，表中 2 条 |

### 4.4 会议变更的字段约束【用例实证】

| 公告类型 | 采编流水号 | 公司部股东大会 id | 公司代码 / 会议名称 / 开会日期 |
| --- | --- | --- | --- |
| 新增 | **有值** | 不变 | 可变 |
| 变更 | 为空 | 变化 | 公司代码、会议名称**不能变** |
| 延期 | 为空 | 变化 | 公司代码、会议名称**不能变** |
| 取消 | 为空 | 变化 | 公司代码、会议名称**不能变** |

## 5. 股权处理自动化（重点模块）

### 5.1 需求背景与目标【需求原文】

> 「为提升用户体验，上市公司点击提交股权处理申请时，新增自动生成说明文稿和提示框内容功能。」

在三阶段优化中，本模块的具体目标是：

1. 提交股权处理申请时的**提示框文字与勾选框改版**；
2. **自动生成每批次申请流程的 PDF 说明文件**并送审统计系统；
3. **自动生成 Word 预览**（置于提示框左侧，支持放大、翻页 / 下拉）；
4. **空流程提交**（后台开放股权处理开关后）：弹确认框，清空已存在流程，定义为「**上市公司主动撤销**」。

> 基础：在《二阶段优化需求方案》已搭建的业务子系统股权处理功能、统计子系统关联任务基本框架上增加优化。

### 5.2 核心操作与术语【需求原文】

| 术语 | 定义 |
| --- | --- |
| **拆分约定卡号** | 对约定卡号执行拆分，拆分后可能存在部分账号无表决权 |
| **剔除表决权** | 剔除部分卡号的表决权 |
| **存在部分投票** | 存在「拆分约定卡号」操作，且**所有拆分账号均有表决权** |
| **存在部分投票和无表决权投票** | 存在「拆分约定卡号」，且**部分拆分账号无表决权** |
| **存在无表决权投票** | 存在「剔除表决权」操作 |
| **空流程 / 主动撤销** | 上市公司提交空流程；后台开放股权处理开关后允许；确认后清空已存在流程，定义为「上市公司主动撤销场景」 |

### 5.3 送审 PDF 文件名规则【需求原文】

```
<公司代码> + 空格 + <公司简称> + "关于股东存在" + <情况清单> + "的情况说明"
```

示例：

```
644997 相关交易所测试关于股东存在部分投票和无表决权投票的情况说明
```

> 测试要点：文件名中的**公司代码、公司简称、情况清单**均随会议信息与操作类型动态变化，需按每种"情况"各验一条。
> 情况清单的拼接方式（多种情况是否用顿号/连接词）**【待确认】**，以原型图/开发实现为准。

### 5.4 提交确认弹窗的组成与交互【需求原文 + 用例实证】

| 组成部分 | 要求 |
| --- | --- |
| **文件预览（Word）** | 位于提示框文字**左侧**；支持放大、翻页 / 下拉条；内容随会议信息、拆分信息**动态更新**，格式与模板一致 |
| **温馨提示（正文）** | 内容正确，其中电话号码为**订单支持人员的座机号码**，后台修改订单支持人员后应**同步更新** |
| **确认复选框** | 不勾选 → 「确认提交」按钮**置灰不可点**；勾选 → 按钮**高亮可点** |
| **按钮：确认提交** | 点击后股权处理提交成功 |
| **按钮：返回检查** | 点击后确认框消失，返回修改数据，再次提交时提示框信息**同步更新** |

**《提示》文案基准（需求原文）**：

> 1. 相关交易所信息网络有限公司仅为上市公司……提供技术性服务，……提供各渠道投票结果的合并统计服务。
> 2. 您所提交的本次股权处理申请将直接影响投票统计结果，请务必审慎提交……提交后如需修改/删除/新增股权处理申请内容，请致电订单支持人员联系方式以测试环境配置为准 重新开启修改开关。若放弃提交，请点击"返回检查"……勾选即表示您已仔细阅读，并充分理解、接受上述提示内容。

### 5.5 开关与流程类型

| 项 | 取值 | 说明 |
| --- | --- | --- |
| 「股权处理」开关 | 开 / 关 | 后台配置；放开后可放开上市公司范围 / 允许修改已提交数据 |
| 「股权文件上传」开关 | 开 / 关 | 后台配置；开启后前台可重新上传股权文件触发空流程或重新提交 |
| 「修改」开关 | 开 / 关 | 提交后需修改需致电订单支持人员重新开启 |
| 流程类型 | `上市公司申请` / `系统自动生成` | 空流程由上市公司提交→`上市公司申请`；股权文件重传触发的空流程→`系统自动生成` |
| 流程状态 | `待审核` / `已撤销`（`已生效` **【待确认】**） | 统计系统侧显示 |

### 5.6 空流程的关键分叉【用例实证】（高频组合，建议做成矩阵）

| 前置 | 前台动作 | 预期 |
| --- | --- | --- |
| 股权处理已提交 + 后台开「股权处理」开关 | 删除股权处理记录后提交 | 弹温馨提示，文案与样式正确，确认/返回按钮正常，**流程类型=上市公司申请** |
| 股权处理已提交 + 后台开「股权文件上传」开关 | 重新上传股权文件提交，**股权处理不操作** | 生成空流程，**流程类型=系统自动生成** |
| 股权处理已提交 + 后台开「股权文件上传」开关 | 重新上传股权文件提交，**提交空流程** | 弹提示：`提交股权处理数据不能为空`（股权文件重传 → 股权处理初始化，作为首次提交） |
| 股权处理页签无数据 | 点击提交 | 报错拦截：`提交股权处理数据不能为空` |
| 模拟环境服务-股权处理页签无数据 | 点击提交 | 报错拦截：`股权拆分文件不能为空` |

### 5.7 提交空流程的业务语义【需求原文】

提交空流程时弹出提示框让上市公司确认；确认则**清空已存在流程**，定义为「**上市公司主动撤销**」。
对应统计系统侧：撤销申请展示正确 & 状态 `待审核`；或最近一个批次股权申请状态更新为 `已撤销`。

### 6.5 系统优化项（202601）【用例实证】

## 8. 术语速查

| 术语 | 含义 |
| --- | --- |
| 会议 / 大会 | 股东大会，平台的核心业务对象 |
| 议案 | 会议下待表决的事项，含 `meetingId` |
| 一次比对 / 二次比对 | 采编数据与上游（自动化抽取、XBRL）数据的比对环节；二次比对对应 VTLS 数据入库 |
| VTLS | 采编二次比对环节的数据来源 |
| XBRL | 上游结构化数据源之一 |
| 股权文件 | 含股东持股明细的文件，按 A股/B股/中登/普通债券/债券定向征集区分 |
