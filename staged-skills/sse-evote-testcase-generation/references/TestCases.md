# TestCases：测试用例生成（Step 3）

## 功能定位

基于 Step2 的测试方案（测试范围 → 测试覆盖大纲），为每个测试点生成 A~P 列结构的详细测试用例，并生成兼容性测试用例 Sheet。产出必须与既有用例库同构，可合并、可统计。

## 前置依赖

- 已完成 Step2，`test_plan.xlsx` 中"测试范围/测试覆盖大纲"已填写。
- **有既有 `test_cases.xlsx` 时必读**：复用模块层级、E 列命名、编号区间与判定口径写法。
- 详细列规范见 `references/用例编写规范.md`（**生成前必须通读**）。

## 模板文件

`templates/测试用例_template.xlsx`，含两个 Sheet：
- `迭代测试用例`（主表，A~P 列）
- `兼容性测试用例`（左右双表 + 分段结构）

**在模板上填充，不要重建表结构**；新增用例追加在末尾，不重排历史行。

## 字段定义（Sheet「迭代测试用例」，顺序与表头固定）

| 列 | 表头 | 来源 / 填写规则 |
| --- | --- | --- |
| A | 所属用例库 | 产品级：`上证e投票平台` / `股东大会信息采编系统` |
| B | 一级模块 | 子系统级：`投票业务子系统` / `数据采编子系统` |
| C | 二级模块 | 用例集级：`迭代版本用例` / `2026版本迭代用例` |
| D | 三级模块 | 需求级：`{迭代}_{需求短名}`，如 `202601_股权处理自动化功能三阶段优化` |
| E | 四级模块 | 功能点，取自方案大纲的**三级/四级条目**；**编号作用域** |
| F | 用例名称 | `编号 + 半角空格 + 场景全景句`，见规范第 3 节 |
| G | 优先级 | `高` / `中` / `低` |
| H | 用例类型 | `功能测试` / `界面测试` / `交互测试` / `边界测试` / `异常测试` |
| I | 前置条件 | `1、…` 编号列表；含环境/账号/数据准备/开关状态 |
| J | 步骤描述 | `1. …` 逐条；内嵌具体测试数据 |
| K | 预期结果 | 与 J 一一对齐；数据类写表名字段；文案类写关键特征 |
| L | 备注 | 默认空；覆盖缺口说明、外部依赖、环境限制 |
| M | 执行结果 | **留空**，Step4 回填 |
| N | 执行人 | 留空或填计划执行人 |
| O | 覆盖范围 | `核心功能` / `一般功能` |
| P | 关联所属需求 | D 列需求短名（可去迭代前缀） |

## 编号规则（硬约束）

1. 编号写在 F 列名称开头，后接**一个半角空格**；
2. 编号在**每个 E 值内从 01 连续自增**；
3. 补零式（`01`）/ 不补零式（`1`）**沿用同一 E 值下的既有风格**；新增 E 值默认补零式；
4. 需求本身仅一条时可不带编号（既有先例）；
5. 追加不重排：新用例接在该 E 值最大编号之后。

## 生成规则

### 从方案到用例的映射

| 方案大纲条目 | 生成用例 |
| --- | --- |
| 三级条目（`1、…`） | 至少 1 条正向用例；含判定细节的细节条目（`1.1、`）可各成一条 |
| 反向/边界类条目 | 各 1 条，类型分别标 `异常测试` / `边界测试` |
| 白名单/范围收口类条目 | 必须生成**反向验证**用例（不开放的类型确实不开放） |
| 数据链路类条目 | 按环节拆：采编侧 / 基础服务侧 / 下游侧各成用例 |
| 组合类条目（开关 × 状态 × 操作） | 用等价类 + 边界取代表值，**不穷举**；选取依据写入 L 列 |

### 覆盖红线

- 每个 E 值：**≥1 条正向 + ≥1 条反向或边界**；缺失需在 L 列说明原因。
- 成对场景必须成对出现：未登录/已登录、前台/后台、首次提交/非首次、单批/历史批次、PC/H5/小程序。
- 禁止只写"数据正确""文案正确""展示正常" —— 必须给判定依据。

### 命名规则

场景全景句：`[端/环境]-[用户状态]-[入口]，[对象/条件]，[操作]，[校验点]`。
词汇表（保持一致性）：
`新网站PC端`、`新网站H5端`、`投票小程序`、`业务系统前台`、`业务系统后台`、`模拟环境服务`、`统计系统`、`采编系统`、`网站后台`、`H5子系统`、`个人用户未登录`、`个人用户已登录`。

## 兼容性测试用例（Sheet「兼容性测试用例」）

- 按 `references/投票业务规则库.md` 第 7 节的矩阵填写（PC 浏览器 × 分辨率；移动端机型）；
- 结构：左右双表 + PC 段 / 移动端段；大类标题行 + 明细行两行一组；
- 配色：浅蓝 `#CCFFFF` 标题区、浅橙 `#FFCC99` 段表头、红字 `#FF0000` 大类行；
- 优先级在本表用**数字 `1`**（沿用原表习惯，不统一为文本）；
- 操作步骤可引用主用例编号（如 `执行用例 05`）。

> 本次需求若不涉及界面改动，可只保留模板骨架并在 L 列/方案风险中说明"本次未涉及兼容性专项"，但**不得删除该 Sheet**。

## 生成步骤

1. **读取方案**：加载 `test_plan.xlsx` 的测试范围内容块。
2. **读取既有用例**（有则）：提取模块层级字典与各 E 值的编号区间。
3. **划分 E 值**：把方案大纲的三级/四级条目归并成"四级模块"。
4. **逐条生成**：按映射规则生成用例，填充 A~P（M/N 留空）。
5. **编号**：按 E 值分组连续编号，追加在既有编号之后。
6. **生成兼容性 Sheet**。
7. **写入并保存** `test_cases.xlsx`。
8. **回执**：向用户报告"共生成 X 条用例，覆盖 Y 个功能点（E 值），其中正向 A 条 / 反向 B 条 / 边界 C 条；未覆盖项与待确认项如下…"。
