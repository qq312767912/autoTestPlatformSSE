# 上证e投票平台 · 测试用例编写规范

> 依据既有产出《202601 上证e投票1月需求版本_系统测试用例》（两个 Sheet：迭代测试用例、兼容性测试用例，80+ 条主用例）归纳。
> 目标：新生成的用例与既有用例库**同构、可合并、可统计**，不引入新的字段习惯。

## 1. 五级模块定位（决定用例归属）

```
A 所属用例库   →  产品/系统级    例：上证e投票平台 / 股东大会信息采编系统
  B 一级模块   →  子系统级      例：投票业务子系统 / 数据采编子系统
    C 二级模块 →  用例集级      例：迭代版本用例 / 2026版本迭代用例
```

## 2. 编号规则

| 规则 | 说明 |
| --- | --- |
| 位置 | 编号写在 **F 列用例名称的开头**，后接**一个半角空格**，不单独设列 |
| 格式 | 两位数字。补零式 `01`、`02`…；不补零式 `1`、`2`… |
| 既有习惯 | 采编类 / 小程序类 / 网站类 / 股权类用**补零式**；下游系统验证类 / 系统优化类用**不补零式** |
| 例外 | 需求本身就是单条时（如"股权文件重传后功能可用优化"），**不带编号**，直接用场景句 |
| 唯一性 | 同一 E 值内连续、不跳号；新增用例**追加到该 E 值末尾**，不重排既有编号（保护历史执行记录） |

## 3. 用例名称写法：场景全景句

**骨架**：

```
[编号] [端/环境]-[用户状态]-[入口]，[对象/条件]，[操作]，[校验点]
```

**既有样例**：

```
01 新网站PC端-个人用户未登录-会议列表，日期控件筛选日期，验证会议数据展示正确
01 业务系统前台-新增股权处理-1条记录-"拆分约定卡号"操作且所有拆分账号均有表决权，点击提交按钮，弹出确认提示框，文件预览信息和温馨提示展示正确
02 人工导入 股票/债券/基金 会议，人工审核通过，数据推送kafka的消息体中包含"timestamp"，vote_basic_info表中新增大会信息的timestamp值与kafka消息一致
```

**书写约定**：

- 层级用 `-` 连接，分句用 `，`；
- 端/环境词汇统一：`新网站PC端`、`新网站H5端`、`投票小程序`、`业务系统前台`、`业务系统后台`、`模拟环境服务`、`统计系统`、`采编系统`、`网站后台`、`H5子系统`；
- 用户状态词汇统一：`个人用户未登录`、`个人用户已登录`、`机构用户`；
- **同一功能的两端状态成对出现**（未登录 / 已登录），两条独立用例；
- 名称需**自解释**：不依赖阅读步骤就能判断这条用例在测什么；
- 避免模糊词（"正常""正确""无异常"）单独成句 —— 必须跟随**判定对象**（如"文件预览信息…展示正确"→ 需在 K 列给出可判定依据）。

## 4. 各列填写规范

### G 优先级

`高` / `中` / `低`。既有产出以 `高` 为主，仅"系统优化"类为 `中`。判定口径：

| 级别 | 适用 |
| --- | --- |
| 高 | 核心业务流程（投票主流程、股权处理提交与审核、数据入库一致性、需求明确变更的交互） |
| 中 | 辅助功能、路径与跳转、样式与文案细节 |
| 低 | 极端边界、兼容性兜底 |

### H 用例类型

`功能测试` / `界面测试` / `交互测试` / `边界测试` / `异常测试`。既有产出以 `功能测试` 为主；需求以交互改版为主的（如提示框）可标注 `交互测试`。

### I 前置条件（最容易被写废的一列）

必须写成编号列表 `1、… \n 2、…`，且**包含下列四类信息中所有适用的部分**：

1. **环境**：子系统 + 必要服务器/日志路径/数据源（如 `kafka topic为INFONET_VOTE.DATA`）；
2. **账号**：角色与状态（如 `个人用户未登录`、`业务系统账号`）；
3. **测试数据准备**：会议类型与数量、股权文件状态、记录条数（如 `已采编 股票会议-纯A股会议、AB股会议、科创板股票会议，会议已同步业务系统`）；
4. **配置与开关状态**：后台开关、上市公司范围放开（如 `业务系统后台设置股权处理放开所有上市公司`）。

**既有样例**：

```
1、已采编 股票会议-纯A股会议、AB股会议、科创板股票会议，会议已同步业务系统
2、业务系统后台设置股权处理放开所有上市公司
3、业务系统前台-股权文件已上传&议案已确认
```

> 纯接口/数据库类用例（如仅校验表结构）可留空；前端展示类用例若无需准备也可留空。**其余情况不得留空**。

### J 步骤描述

- 每条用 `1. ` `2. ` `3. ` 逐条编号换行；
- 步骤必须是**可执行动作**（在哪、点什么、填什么），而不是"验证 XX"；
- **内嵌具体测试数据**：卡号（如 `D000000001`）、URL、任务号（如 `C0005`、`V0408`）、记录条数；
- 粒度：一条用例 3–8 步为宜；超过 8 步通常应拆分。

**既有样例**：

```
1. 股东会模块-会议列表选择对应会议，点击进入编辑按钮
2. 信息确认节点-股权处理页签，新增股权处理-1条记录-"拆分约定卡号"操作且所有拆分账号均有表决权
3. 信息确认节点-股权处理页签，点击提交按钮
4. 文件预览信息验证
5. 温馨提示信息验证
```

### K 预期结果

- **与 J 的步骤编号一一对齐**（J 有 5 步，K 就有 5 条）；
- 每条预期必须**可观测、可判定**：写明"看哪里 + 比什么"；
- 复杂业务可追加**"…定义为：…"**的补充行，把判定口径写清楚（既有产出即采用此法）：

```
4. 格式同模板一致，模板中根据会议信息、拆分信息 动态更新的数据展示正确。
拆分情况定义为：存在部分投票
5. 内容正确，其中电话号码为订单支持人员的座机号码
```

- 数据类用例必须写**表名 + 字段名 + 取值关系**：

```
1. vote_basic_info 有时间戳字段：timestamp
2. vote_basic_info_error 有时间戳字段：timestamp
```

### L 备注

默认留空。以下情形必须填写：

- 该功能点**缺少反向或边界场景**的原因说明；
- 依赖外部人工配合（"需项目组配合造数"）；
- 已知环境限制（"当前环境无法验证，仅记录"）。

### M / N 列

生成时留空（M 执行结果、N 执行人），由 Step4 执行时回填。

### O 覆盖范围

`核心功能` / `一般功能`。

### P 关联所属需求

填写 D 列的**需求短名**（可去掉 `202601_` 前缀），用于按需求汇总。

## 5. 拆分与覆盖原则

| 原则 | 说明 |
| --- | --- |
| 一操作一用例 | 相同步骤 + 不同数据/状态 → 拆成不同用例，**不合并** |
| 正反成对 | 每个功能点至少 1 条正向 + 1 条反向/边界 |
| 状态成对 | 未登录 / 已登录、前台 / 后台、首次 / 非首次、单批 / 历史批次 |
| 链路不跨用例 | 端到端链路过长时按"环节"拆（采编侧 / 基础服务侧 / 下游侧各成用例），避免一条用例 15 步 |
| 组合取代表值 | 组合爆炸时（开关 × 状态 × 操作），用**等价类 + 边界**取代表值，并在备注说明选取依据 |

## 6. Sheet「兼容性测试用例」规范

与主用例表分开存放在同一 `test_cases.xlsx` 的第二个 Sheet，采用**左右双表 + 分段**结构：

```
左表 A–C 列：操作系统 / 版本 / 浏览器版本（PC 段）
右表 E–K 列：屏幕分辨率 / 优先级 / 操作步骤 / 期望输出 / 执行结果 / 执行人 / 备注

PC 段（浏览器 × 分辨率）
移动端段（机型：iOS / 鸿蒙 / 安卓）—— 表头字段随之改名：
   浏览器版本 → 操作步骤；执行结果结果 → 测试结果
```

- 每个大类（360 系列 / Chrome 系列 / 奇安信浏览器 / 统信浏览器 / IOS / 鸿蒙 / 安卓）为**大类标题行 + 明细行**两行一组；大类行整行合并；
- **配色约定**：浅蓝 `#CCFFFF` = 标题区；浅橙 `#FFCC99` = 段表头；红字 `#FF0000` = 大类标题行；纯白 `#FFFFFF` = 特殊单元格；
- 优先级在此表使用**数字**（`1`）—— 与主表的文本优先级（`高`/`中`）不一致，**沿用原表习惯，不要自行统一**；
- 兼容性表通常**不逐条展开业务步骤**，操作步骤可引用主用例编号（如 `执行用例 05`）。

## 7. 常见反例（生成后自检）

| 反例 | 问题 | 改法 |
| --- | --- | --- |
| K 列写"页面展示正确" | 无判定标准，不可复现 | 写明"看哪个区域、与什么比对（需求原型图第 N 页 / 表字段值）" |
| J 有 7 步，K 只有 2 条 | 无法判定哪步失败 | 预期按步编号对齐 |
| I 列写"环境正常" | 前置不可执行 | 写出环境、账号、数据、开关四要素 |
| 用例名称只有"验证股权处理" | 无法判断测试意图 | 用场景全景句补齐端/状态/条件/校验点 |
| 一条用例既测提交又测审核又测统计 | 失败定位困难 | 按子系统拆成 3 条 |
| 编号不连续 / 跳号 | 破坏可追溯性 | 同 E 值内连续编号 |
