# 上证e投票平台测试用例生成

本 Skill 承担四阶段测试链路中的**用例生成阶段**，将已通过门禁的测试方案逐项转换为可执行、可复现、可判定的测试用例。

## 前置门禁与输入

- 必须提供同一 `workflow_id` 下已通过质量门禁的 `test_plan.xlsx` 与方案项 ID；缺少产出引用或门禁未通过时停止，不绕过。
- 有历史 `test_cases.xlsx` 时必须读取，用于复用模块层级、编号风格与已有编号范围。
- 用例写法以 `references/用例编写规范.md` 为准，业务基准以 `references/投票业务规则库.md` 为准。

## 执行流程

1. 将方案末级条目映射为用例功能点和关联 `plan_item_id`，不得丢弃方案中的需求或风险点。
2. 按 `references/TestCases.md` 和 `templates/测试用例_template.xlsx` 填写 A~P 列，保留模板双 Sheet 结构并在末尾追加，不重排历史用例。
3. 对每个功能点生成正向用例及至少一条反向或边界用例；白名单必须验证禁止范围确实不可用；数据链路按采编、基础服务、下游环节拆开；组合场景用等价类及边界值选取代表值并记录依据。
4. 每条用例明确环境、角色、数据、开关等前置条件，步骤内写入具体可用测试数据，预期结果与步骤逐条对应且给出可观察判据。未知业务规则列入待确认，不臆造预期。
5. 按 E 列功能点编号；F 列名称以编号和一个半角空格开头。新用例默认补零，并沿用已有模块下最大编号继续追加。M 执行结果与 N 执行人留空。
6. 生成兼容性 Sheet；本轮不涉及 UI 变更时保留模板骨架并说明原因，不删除该 Sheet。
7. 自检表头、编号、方案追溯、步骤/预期对应、正反边界覆盖、成对状态、多端和数据判据；输出覆盖率、缺口与待确认项。

## 质量门禁

- 每条用例关联至少一个有效方案项 ID；P0 方案项覆盖率须为 100%。
- 禁止“数据正确”“文案正确”“展示正常”等无判据预期。
- 方案未覆盖、待确认或阻塞项不得伪装成已覆盖。
- 输出 `test_cases.xlsx` 与结构化用例集；用例门禁通过后才进入执行阶段。
