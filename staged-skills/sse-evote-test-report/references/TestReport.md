# TestReport：测试报告生成（Step 5）

## 功能定位

基于 Step4 的执行结果（回填后的 `test_cases.xlsx`、截图、证据、日志），生成单文件 HTML 测试报告，提供测试概览、模块分组、用例详情、失败追溯与**回归结论**。

> 本平台报告除"执行统计"外，必须回答两个业务问题：**①本次需求点是否全部验证到位（含范围收口类需求）；②回归是否完成、有哪些未覆盖项与遗留风险。**

## 前置依赖

- 已完成 Step4，`test_cases.xlsx` 的 M 列已更新（通过/失败/阻塞）。
- `screenshots/` 存在且文件名与用例编号对应。
- `evidence/`、`test_config.json`、`logs/execution.log` 存在（用于追加证据与配置摘要）。

## 输出产物

```
{OUTPUT_ROOT}/
├── test_report.html      # 主报告（单文件，可离线查看）
├── test_results.json     # 结构化结果（含原始统计，供二次分析）
└── screenshots/          # 已被报告引用
```

## 数据来源

| 数据项 | 来源 |
| --- | --- |
| 用例列表与结果 | `test_cases.xlsx` → Sheet「迭代测试用例」 |
| 模块归属 | 同上：A/B/D/E 列（**按 D 列需求 + E 列功能点分组**，不是只按一级模块） |
| 截图 | `screenshots/{用例编号}_*.png` |
| 数据证据 | `evidence/{用例编号}_*` |
| 执行配置 | `test_config.json` |
| 起止时间与耗时 | `logs/execution.log` 或 `test_results.json` |
| 回归范围 | `references/回归清单.md` + 方案中本次裁剪后的回归段 |

## 统计口径（必须在报告中显式声明）

| 指标 | 公式 |
| --- | --- |
| 通过率（总） | 通过 ÷ (通过 + 失败) × 100%（**阻塞不计入分母**，单独列出） |
| 阻塞数 | 单独列出，并附阻塞原因分布 |
| 按需求统计 | 按 D 列分组，给出各需求的用例数 / 通过率 |
| 按功能点统计 | 按 E 列分组，便于定位漏测区域 |
| 按执行方式统计 | A 类自动化 / B 类数据校验 / C 类人工 三种口径分别给出数量与结果 |
| 按覆盖范围统计 | `核心功能` 的通过率单独展示（作为发布结论主依据） |

> ⚠️ 分母口径必须在报告中写明。**分母中剔除阻塞必须显式声明**，否则通过率不可信。

## 报告结构

### 1. 头部概览

- 报告标题：`{产品}_{迭代需求}_系统测试报告`
- 关键信息行：测试环境、执行人、执行时间、轮次
- 全局通过率进度条 / 圆环（SVG 或 CSS）
- 关键数字卡片：总用例 / 通过 / 失败 / 阻塞 / 通过率 / 核心功能通过率

### 2. 需求覆盖结论（本平台特色，必含）

逐条列出本次需求点，给出「验证结论」与「用例编号区间」：

| 需求项 | 覆盖功能点数 | 用例数 | 结论 | 备注 |
| --- | --- | --- | --- | --- |
| 新版网站优化 | 3 | 10 | 通过 | — |
| 采编系统时间戳/唯一性约束 | 3 | 26 | 通过 | 含 3 条异常表用例 |
| 股权处理自动化三阶段 | 4 | 30 | 通过 | 白名单反向验证已覆盖 |

**范围收口类需求单独列示**（如"仅 A 股/AB 股开放股权处理"），并给出**反向验证结论**。

### 3. 模块与用例明细

- 按 D 列（需求）→ E 列（功能点）两级折叠分组（`<details>/<summary>`，默认展开）；
- 分组标题显示：功能点名称 + 通过率 + 失败数/总数；
- 表格列定义（固定百分比）：

| 列名 | 宽度 | 说明 |
| --- | --- | --- |
| 用例编号 | 6% | F 列名称前缀 |
| 功能点 | 12% | E 列 |
| 用例名称 | 18% | 超长省略 + hover 展示全文 |
| 优先级 | 6% | 高 / 中 / 低 |
| 预期结果 | 22% | 多行，默认首行，hover 浮层全文 |
| 测试结果 | 8% | 状态 badge |
| 证据 | 9% | 截图缩略图（40×40，点击放大）/ 数据证据链接 |
| 验证备注 | 19% | 失败摘要 / 阻塞原因 / 人工确认提示 |

- 长文本列设置 `max-width` + 省略号 + hover tooltip；双击复制单元格内容。

### 4. 失败与阻塞清单

- **失败**：用例编号、名称、失败步骤、实际结果、证据链接、疑似模块；
- **阻塞**：用例编号、阻塞原因（数据未就绪 / 环境不可用 / 依赖外部配合）、责任人、预计解除时间；
- **需人工二次确认**：无法自动验证的步骤清单。

### 5. 回归结论

按 `references/回归清单.md` 的子系统分组，给出：

| 子系统 | 是否纳入本次回归 | 用例数 | 通过率 | 未覆盖项及原因 |
| --- | --- | --- | --- | --- |
| 业务系统（前台/后台） | 是 | … | … | — |
| 现场服务工具 | 是 | … | … | — |
| 投票小程序 | 是 | … | … | … |
| 统计系统 | 是 | … | … | — |
| 采编系统 | 是 | … | … | — |
| 新网站 H5 端 | 是 | … | … | … |

### 6. 未覆盖项与遗留风险

- 未覆盖的浏览器 / 机型（引用兼容性矩阵）；
- 环境限制导致的未验证项；
- 本轮未修复的已知问题及其影响范围；
- 明确表述：**"本结论不隐含未覆盖项已验证通过"**。

### 7. 执行配置摘要

环境、浏览器、执行模式、并发数、重试次数、数据校验配置（**脱敏**）。

## UI 规范

- 页面宽度 1200px，居中，浅色背景 + 圆角卡片；
- 状态色（沿用团队习惯）：

| 状态 | 背景 | 文字 |
| --- | --- | --- |
| 通过 | `#e8f8ef` | `#27ae60` |
| 失败 | `#fdecea` | `#e74c3c` |
| 阻塞 | `#fff8e8` | `#d4900a` |

- 表格隔行浅灰底纹；
- 中文字体栈；
- 交互：折叠、tooltip、双击复制、截图 lightbox（同用例多图可左右切换）。

## 生成步骤

1. 解析 `test_cases.xlsx`（A~P 全列）；
2. 建立截图/证据映射：`{用例编号}_*` → 用例；
3. 计算统计指标（多种口径，见上）；
4. 生成需求覆盖结论与回归结论（结合方案的需求段与 `references/回归清单.md`）；
5. 输出 `test_report.html`；
6. 序列化统计数据与用例明细为 `test_results.json`；
7. 若 M 列为空或全部未执行，**先提示用户完成 Step4**，不要生成空报告。

## 注意事项

- **不得美化数据**：失败/阻塞必须如实呈现；未覆盖项不得省略。
- 不得用"全部通过"替代分项结论；**阻塞项必须出现在报告的显著位置**。
- 报告需可离线打开（单文件，图片内联或相对路径引用本地截图目录）。
- 结论措辞应与执行证据强度一致：人工抽查≠全量验证，不要写成"全面验证通过"。
