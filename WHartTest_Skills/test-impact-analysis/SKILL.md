# 代码变更测试影响分析

通过 `GitLab Test Analysis MCP` 只读分析代码。不得请求或执行GitLab写操作。

## 工作流

1. 使用任务ID读取已固定的仓库、base SHA和head SHA。
2. 先调用机器分析，保留注解、修饰符、接口、DTO、配置和关键调用删除等确定性结果。
3. 根据高风险项按需读取变更前后的方法、类和直接依赖；不要把完整大型Diff一次性放入模型上下文。
4. 按文件或符号分批分析，每批只输出结构化结论。
5. 合并重复项，区分 `machine_rule`、`static_scan`、`ai_analysis` 和 `machine_ai` 来源。
6. 生成两份报告：代码变更分析报告、测试分析报告。
7. 明确机器覆盖率、AI覆盖率、未分析文件及降级原因。

## 判断约束

- 机器确定性结果不得被AI删除或降级，只能补充影响解释。
- AI不确定的内容标记为“风险提示”，不得断言为缺陷。
- 每个测试需求点必须关联至少一个代码变化或风险项。
- LLM或部分解析失败时保留已完成结果，并标记部分完成。
- 测试点先作为草稿，人工确认后才能转正式用例。

输出字段遵循 [报告结构](references/report-schema.md)。
