# 测试用例清晰度审查

把测试用例当作可独立执行、可复现、可判定的验收说明进行审查。目标是找出可能造成漏测、误判或人员交接失真的问题，并给出尽量小而具体的修改建议。

## 输入处理

- 接受表格、文档、Markdown、纯文本、截图识别结果或从用例平台导出的内容。
- 保留用例原有编号、模块和名称，便于问题回写。
- 输入较多时逐条扫描，并汇总重复出现的系统性问题。
- 缺少需求、字段基线或业务规则时继续审查现有文本；不要凭空补造业务预期，把无法确定的内容标记为“待业务确认”。

## 审查方法

1. 识别用例的前置条件、测试数据、操作步骤和预期结果；缺失的部分明确指出。
2. 逐个步骤检查是否有对应的可观察结果，并检查每条预期能否被实际步骤触发和验证。
3. 按 [审查规则](references/review-rules.md) 扫描模糊措辞、判定基线、数据、覆盖、证据和可维护性问题。
4. 区分问题性质：
   - **确定缺陷**：仅根据用例文本即可确认，例如“显示正确”没有判定标准。
   - **待业务确认**：需要需求、原型、接口契约或字段清单才能确定，例如应导出哪些列。
   - **优化建议**：不影响当前执行，但能降低交接或回归风险。
5. 建议应贴合当前业务语境。能从输入确定具体标准时，直接给出改写；不能确定时，提供带占位符的改写模板，并列出需要确认的信息。

## 交付物

每次扫描都必须生成一个可下载、可归档的独立审查报告文件。只在对话中返回扫描结论不算完成。

- 用户指定格式时按用户要求生成。
- 用户未指定时默认生成 Markdown 报告；当源文件是表格且问题明细较多、需要筛选或分派整改时，优先生成 Excel 报告。
- 报告文件名使用 `<源文件名>_测试用例质量审查报告.<扩展名>`；没有源文件名时使用 `测试用例质量审查报告_<日期>.<扩展名>`。
- 报告必须能追溯到原用例，保留源文件、Sheet、行号/用例编号、模块和用例名称；不得只给出脱离原文的汇总数字。
- 不覆盖或修改原始用例文件，除非用户明确要求回写。
- 最终回复提供报告链接，并仅概括最重要结论；完整问题明细以报告为准。

报告至少包含：

1. **基本信息**：源文件、扫描范围、扫描时间、用例总数和审查口径。
2. **执行摘要**：问题用例数、严重程度分布、主要风险和优先整改范围。
3. **问题分布**：按问题类型、模块、优先级汇总。
4. **问题明细**：原用例位置、原文、严重程度、问题类型、问题说明、修改建议和判定性质。
5. **改写示例**：至少覆盖高风险或重复性最高的问题。
6. **待确认事项**：需要产品、开发或内部测试负责人补充的业务基线。
7. **治理建议**：针对重复问题提出模板、交接、评审或门禁改进。

若扫描工具或文本规则先产生候选项，应在报告中区分“规则命中数”和“复核后确认/建议复审数”，不得把关键词命中直接描述为确定缺陷。

## 报告内容要求

先给出总体结论，包括用例数量、存在问题的用例数量、严重程度分布和最常见问题。随后输出问题明细：

| 用例编号/名称 | 位置或原文 | 严重程度 | 问题类型 | 问题说明 | 修改建议 | 判定 |
|---|---|---|---|---|---|---|

严重程度按风险而非文字数量判断：

- **高**：可能让核心功能错误仍被判定通过，例如只检查“导出成功”而不检查关键内容。
- **中**：可能造成不同执行人得出不同结论，或遗漏边界、异常和数据一致性检查。
- **低**：主要影响效率、维护性或证据追溯。

明细之后提供：

- 可直接替换的改写示例，优先覆盖高风险问题。
- 需要产品、开发或内部测试负责人确认的事项。
- 重复性问题的治理建议，例如统一模板、字段基线或评审门禁。

若用户要求输出修订后的完整用例，在不改变已知业务含义的前提下重写；新增但尚未确认的内容必须标注 `[待确认]`，不得伪装成既定需求。

## 完成条件

只有同时满足以下条件才可结束：

- 已扫描用户要求的全部范围，或在报告中明确记录未扫描范围及原因。
- 汇总数字可以与问题明细对应，不重复累计同一用例。
- 高风险问题经过语义复核，避免仅凭关键词机械定级。
- 独立审查报告已成功保存并可供用户打开。
- 最终回复已交付报告文件，并说明最优先处理的风险。

## 质量边界

- 不因出现“正常”“正确”等词就机械判错；若同一句已经给出明确可观测标准，可以通过。
- 不把“增加更多用例”当作所有问题的默认答案；优先修复原用例的判定能力。
- 不仅检查措辞，也检查最终业务结果。例如下载成功不等于文件内容完整。
- 不将测试人员经验、口头约定或历史认知视为可传承的验收标准。
- 不归责个人。将问题定位到用例、需求基线、交接或流程中的具体缺口。
