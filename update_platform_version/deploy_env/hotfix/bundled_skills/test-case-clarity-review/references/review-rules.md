# 审查规则

按风险选择适用规则，不要求每条用例机械具备所有要素。

## 1. 模糊和不可判定表述

重点识别：正常、正确、成功、无误、无异常、符合预期、展示正常、功能可用、数据没问题、无乱码、适当、及时、友好、完整等。

只有在缺少具体判定标准时才报告问题。建议补充可观察对象及基线，例如状态码、页面状态、字段名称、数量、顺序、格式、范围、时限、数据来源或错误提示。

示例：

- 原文：“验证导出成功，Excel 展示正确无乱码。”
- 问题：只能证明文件可下载和中文可读，不能证明表头、字段、行数及业务值完整正确。
- 改写：“文件可下载并由 Excel 打开；Sheet 名称为 `[待确认]`；表头与字段基线一致；数据行数与查询结果一致；抽查首、中、末行的关键字段；中文及特殊字符不出现乱码。”

## 2. 前置条件与测试数据

检查用户角色与权限、环境与配置、关键测试数据及唯一标识、数据准备方法，以及时间、地区、币种、租户等会改变结果的上下文。

如果任意数据都能得到相同结论，不强求固定值；如果结果依赖数据内容，则必须给出输入与预期对应关系。

## 3. 步骤可执行性

检查操作对象、入口和动作是否明确；顺序是否完整；是否依赖未说明的隐含操作；一个步骤是否混入多个难以定位失败原因的动作；是否存在步骤没有预期，或预期没有对应触发步骤。

不要过度要求按钮坐标或纯界面细节；只保留影响复现和判定的信息。

## 4. 预期结果完整性

预期应覆盖真正交付的业务结果，而不只是过程信号：

- 提交成功之外，检查数据是否落库、状态是否变化、下游是否一致。
- 导出成功之外，检查文件结构、字段完整性、数据一致性和格式。
- 接口返回 200 之外，检查业务码、关键响应字段和副作用。
- 消息发送成功之外，检查接收对象、内容、次数和时效。
- 页面提示成功之外，检查刷新、重新登录或重新查询后的持久状态。

检查数量、顺序、格式、精度、空值、重复、映射转换和关联关系是否在当前风险下需要明确。

## 5. 正向、异常与边界覆盖

根据场景风险检查必填与可选、合法与非法、空值与零值、最大最小值、超长与特殊字符、重复提交、权限不足、状态不允许、并发操作、无数据与多数据、失败后的提示与回滚。

只报告与当前功能和风险有关的缺口，不罗列无关边界组合。

## 6. 数据一致性与来源

出现“数据一致”“内容正确”时，应明确比较双方及规则，例如 Excel 与页面查询结果、页面与接口响应、汇总值与明细计算结果、操作前与操作后状态。

指出抽样策略是否足够。关键字段缺失风险高时，表头通常应全量校验，数据可以按风险抽查首行、中间行、末行和特殊数据行。

## 7. 证据与可追溯性

对外包交付、生产回归或关键功能，检查是否要求保存足以复核结论的证据，例如原始导出文件、页面截图、日志、请求响应、执行版本、环境、时间和测试数据标识。证据应服务于复核，不要为了截图而截图。

## 8. 可维护性与交接

检查用例是否依赖执行人的口头知识；“参考线上”“同以前”“按需求”等引用能否定位到版本化基线；字段清单、权限矩阵和状态流转是否适合抽成公共基线；名称能否说明对象、条件和行为；重复用例是否已经发生规则漂移。

## 9. 严重程度参考

- 高：缺失关键业务结果、没有通过/失败基线、错误也可能通过、核心权限或资金状态未校验。
- 中：数据或条件不充分、边界与异常缺失、步骤预期映射不清、不同人员可能作出不同判断。
- 低：命名、证据、复用和维护性问题，对当前判定影响较小。

同一根因造成多个文字问题时尽量合并，避免用大量低价值告警淹没关键风险。
